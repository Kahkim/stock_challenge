# 모의주식 챌린지

참가코드 하나로 모여서 10~20분 동안 모의 주식을 사고파는 실시간 웹 게임.
최종 자산이 가장 높은 사람이 이깁니다.

서버(게임 엔진 + API)와 화면이 한 저장소에 들어 있습니다.
서버를 띄우면 같은 주소에서 화면까지 바로 뜹니다. 서버와 화면의 계약은
[`docs/API.md`](docs/API.md) 에 전부 정리돼 있습니다.

```bash
node server.js               # http://localhost:3000 — 화면까지 같이 뜬다
npm test                     # 엔진 36 + 방 18 + API 42 = 96개
node tests/load.test.js 50   # 사람 50명 동시접속 부하 테스트
node tools/balance.js        # 설정을 바꾼 뒤 밸런스가 깨지지 않았는지 측정 — 사람 11·33·55명을 한 번에 잰다
```

방장이 방을 만들면 6자리 참가코드가 나옵니다. 참가자는 같은 주소에 들어와
그 코드를 넣으면 됩니다. 새로고침하거나 잠깐 끊겨도 원래 자리로 돌아옵니다.

외부 의존성이 없습니다. Node 18 이상이면 그대로 돌아갑니다.

## 행사 운영에 필요한 것들

| | |
|---|---|
| **재접속 복구** | `join` 에 `deviceId` 를 같이 보내면 새로고침해도 원래 참가자로 복귀합니다. 게임이 시작된 뒤에도 복귀는 되고 난입만 막힙니다 |
| **영속성** | 방 상태를 10초마다 저장합니다. 서버가 죽어도 재시작하면 그 지점부터 이어갑니다 (`PERSIST_DIR`) |
| **일시정지** | `POST /pause` · `/resume-game`. 틱을 멈추면 게임 시간도 같이 멈춥니다 |
| **참가자 내보내기** | `POST /kick`. 삭제가 아니라 차단입니다 — 지우면 그 사람 주식이 증발해 총량 보존이 깨집니다 |
| **시작 전 설정 변경** | `POST /config`. 사람이 예상보다 적게/많이 왔을 때. 참가자 토큰은 유지됩니다 |
| **결과 내려받기** | `GET /result.csv` (UTF-8 BOM, 엑셀에서 한글 안 깨짐) |
| **요청 제한** | 참가자 토큰 기준 초당 12건. 행사장 WiFi 는 50명이 한 IP 를 쓰므로 IP 기준은 느슨합니다 |
| **판 재현** | `config.seed` 를 고정하면 같은 게임이 그대로 재현됩니다. 리허설용 |
| **방 자동 정리** | 마감 뒤 30분(`ROOM_ENDED_MS`), 마지막 활동 뒤 4시간(`ROOM_IDLE_MS`)이 지난 방을 1분마다 걷어냅니다. 방이 걷히면 결과 조회도 닫히니 **시상·정산과 CSV 내려받기는 마감 뒤 30분 안에** 끝내세요 |

## 게임 구조

```
로비 → 개장 공모(45초) → 정규장(15분) → 마감
```

- **시작 자산은 현금 100만원뿐입니다.** 주식은 0주로 시작합니다.
- **개장 공모**에서 가격과 수량을 써내면 단일가로 시초가가 정해지고 주식이 배정됩니다.
  시초가는 설정값이 아니라 **참가자들의 청약 결과**로 만들어집니다.
  공모가는 기준가 밑으로 내려가지 않습니다 — 기준가 미만 청약은 배정되지 않고 환급됩니다.
- 매분 **월급**(현금)이 들어오고, 동시에 주식 보유자에게만 **무상증자**가 배정됩니다.
- 매분 전 종목의 **적정가**가 조금씩 오릅니다(인플레이션). 현금은 액수가 그대로라 상대적으로 가치가 떨어집니다.
- 거래는 실제 증권시장과 같은 **연속경쟁매매**(가격 우선 → 시간 우선)입니다.
- 평균 70초마다 **돌발뉴스**(호재/악재)가 터지고, 봇들이 **시차를 두고** 동조합니다.
- 이 경제에서는 '매분 월급을 아무 종목에나 넣기'가 가장 강합니다(아래 '밸런스에 관한 기록'). 그걸 바꾼 **시장조성자 경제**가
  설정 묶음(`PRESETS.marketMaker`)으로 준비돼 있습니다 — 무상증자 대신 시초가 프리미엄, 시장조성자가 적정가에 호가를 댑니다. 기본은 끔.

## 설정

전부 `src/config.js` 의 기본값이고, 방을 만들 때 화면에서 덮어쓸 수 있습니다.

| 항목 | 기본값 |
|---|---|
| 종목 | 10종목 풀에서 선택 (기본 6종목). 사람 40명 이상이면 6종목 이하 권장 — 10종목은 봇 30명이 얇게 퍼져 매도 호가가 40% 빈다 |
| 시드머니 | 1,000,000원 |
| 시작 주식 | 0주 |
| 발행 시가총액 | 시드머니 총액의 150% (기준가 기준). 청약 수요가 이보다 적어 기준가 이상 청약분이 전량 발행된다 |
| 월급 | 100,000원 / 1분 |
| 인플레이션 | 0.5% / 1분 (적정가 상승 방식) |
| 무상증자 | 1회 최대 5% |
| 정규장 | 15분 |
| 개장 공모 | 45초 |
| 공모가 하한 | 기준가 (그 미만 청약은 배정 제외) |
| 최소 거래 단위 | 10주 |
| 호가 단위 | 2,000원 미만 5원 / 5,000원 미만 10원 / 그 이상 25원 |
| 수수료 | 편도 0.15% |
| NPC 봇 | 30명 (순위에서는 제외) |
| 돌발뉴스 | 평균 70초 간격, 호재:악재 = 5:5, 효력 90초 |
| 공모 청약 비중 | 봇이 현금의 30%부터 청약 (시장에 풀리는 주식량을 정한다) |
| 호가 사다리 | 호가 제시형 봇이 4단계에 걸쳐 호가를 깐다 |
| 시초가 프리미엄 · 시장조성자 | 끔 (시장조성자 경제 프리셋에서 30% · 켬) |

종목을 바꾸려면 `src/config.js` 의 `STOCK_POOL` 만 고치면 됩니다.

## NPC 봇

봇은 **사람과 완전히 동일한 조건**으로 참가합니다. 같은 시드머니, 같은 월급, 같은 인플레이션을 받고,
사람 화면에 보이는 정보(현재가·적정가·최근 추세·자기 잔고)만 봅니다.
남의 미체결 주문이나 보유내역은 보지 않습니다 — 서버가 볼 수 있다고 해서 보여주면
봇이 구조적 내부자가 되고 게임의 정당성이 무너집니다.

시장의 성격은 봇 한 명의 알고리즘이 아니라 **봇 집단의 성향 구성비**로 조절합니다.

| 성향 | 기본 비중 | 하는 일 |
|---|---|---|
| `trend` | 60% | 오른 종목에 올라탄다 — 시장에 모멘텀을 만든다 |
| `maker` | 20% | 종목 견해 없이 양방향 호가를 낸다 — 호가창이 한쪽만 차는 걸 막는다 |
| `noise` | 15% | 봇마다 고정된 무작위 취향 |
| `contra` | 3% | 내린 종목을 줍는다 — 버블이 무한히 커지지 않게 잡는다 |
| `value` | 2% | 적정가 대비 싼 종목을 산다 — 인플레이션을 체결가로 전달한다 |

`lookbackSec`(기본 120초)이 가장 중요한 다이얼입니다. 봇이 추세를 판단하는 창인데,
길수록 봇이 느리게 반응해서 짧은 창을 보는 사람이 **먼저** 올라탈 수 있습니다.
30초로 줄이면 봇이 사람보다 빨라져 추격매매가 오히려 손해가 됩니다.

## 구조

```
server.js            HTTP + SSE. 라우팅과 인증, 요청 제한
src/config.js        모든 기본값과 종목 풀
src/orderbook.js     연속경쟁매매 오더북 (가격 우선 → 시간 우선)
src/game.js          게임 엔진 — 공모, 체결 정산, 월급, 증자, 인플레, 뉴스, 순위, 직렬화
src/bots.js          NPC 참가자 의사결정
src/news.js          돌발뉴스 생성과 봇 동조
src/rooms.js         방 관리, 참가코드, 재접속, 설정값 검증

src/ratelimit.js     토큰 버킷 요청 제한

prototype/           서버 없이 혼자 도는 화면 데모 (더미 엔진 내장, 디자인 확인용)
tests/engine.test.js 엔진 27개
tests/rooms.test.js  방 정리(sweep) 18개
tests/api.test.js    API 42개
tests/load.test.js   50명 동시접속 부하
tools/balance.js     밸런스 측정 도구

```

화면은 `public/index.html` 한 파일입니다. 빌드 단계도, 프레임워크도, 외부 스크립트도
없습니다. 실시간 갱신은 SSE(`/stream`)로 받고 주문은 평범한 POST 로 보냅니다.

## 밸런스에 관한 기록

설계값은 감이 아니라 측정으로 정했습니다. 아래는 전부 시뮬레이션으로 확인된 사실입니다.

**밸런스는 방 크기에 따라 달라집니다 — 그래서 세 가지 인원으로 잽니다.** 처음 설계값(발행 시가총액 60%)은
사람 24명·봇 50명에서 맞춘 것이었는데, 실제 기본값은 봇 30명이고 행사장에는 사람이 30~50명 옵니다.
그 조건에서 재 보니 사람이 24명만 넘어도 매도 호가가 30% 넘게 비고, 뉴스에 2초 만에 반응한 사람이
그냥 들고 있는 사람보다 뒤처졌습니다. 공모에서 청약이 잘려 시장이 구조적으로 현금 과잉이었고,
사람이 많을수록 그 현금이 얇은 매도 호가를 한 번에 쓸어버려 먼저 산 사람이 '마지막 매수자'가 됐기 때문입니다.
봇 성향·행동률·뉴스 세기·월급·증자를 바꿔도 안 고쳐졌고, 봇을 80명으로 늘리거나
**발행 시가총액을 올리는 것**만 통했습니다. 100%는 48명 방에 월급을 매분 전부 쏟는 참가자가 섞이면
다시 깨졌고(매도 호가 34% 공백), 150%부터 사람 8·24·48명 전 구간에서 여섯 판정이 전부 통과합니다.
그 이상은 청약 수요가 상한이라 발행량이 더 늘지 않습니다.

| 사람 수 (봇 30) | 발행 60% | 발행 150% |
|---|---|---|
| 8명 | 통과 | 통과 (뉴스 2.7 · 추격 3.2 · 보유 4.5 · 뒷북 5.8 · 무행동 7.5) |
| 24명 | 매도호가 37% 공백 · 뉴스대응 11.8등 vs 보유 9.1등 | 통과 (뉴스 6.7 · 추격 9.5 · 보유 12.2 · 뒷북 18.6 · 무행동 22.5) |
| 48명 | 매도호가 54% 공백 · 뉴스대응 28.5등 vs 보유 11.3등 | 통과 (뉴스 13.6 · 추격 19.9 · 보유 22.6 · 뒷북 36.8 · 무행동 45.0) |

**공모가에는 하한이 있어야 합니다.** 발행량을 올리면 공모가 미달되는데, 단일가 배정에서 미달이면
'가장 낮은 청약가'가 공모가가 됩니다. 누가 10주를 5원에 써내면 전원이 5원에 배정받는 구멍입니다.
그래서 기준가를 하한으로 두고 그 밑의 청약은 배정하지 않습니다. 봇도 이 규칙을 알고 기준가 이상으로만 청약합니다.

**가장 강한 전략은 '매분 월급을 전부 아무 종목에나 넣는 것'입니다.** 도구를 시장가 주문(화면 기본값)과 사람 33명·봇 30명·24회로
다시 재면 20초마다 무작위 종목을 사기만 하는 '막사기'가 4.3등, 매분 월급을 전 종목에 나눠 넣는 전액 투자 6.8등, 한 종목 몰빵 8.9등이고,
상시 투자에 뉴스까지 대응하는 유능한 참가자가 10.6등, 뉴스 대응만 하면 17.8등, 공모 후 보유 22.4등, 무행동 32.0등입니다.
무상증자가 보유 주식에 매분 5%를 얹고 월급 유입이 주가를 밀어 올리니(평균 주가 +15.9%), 현금을 들고 있는 시간이 곧 손해입니다.
뉴스·추세 판단은 그 위에 몇 %p를 더하는 정도이고, 전액 투자 상태에서 뉴스에 따라 종목을 갈아타면 호가 충격 비용이 뉴스 수익보다 커서
오히려 손해였습니다. 여기에 사람들의 시장가 매수가 얇은 매도 호가(공백 49%)를 사다리째 쓸어 올리고 그 체결가가 곧 전원의 평가액이 되는
효과가 겹칩니다.

**값 조정으로는 안 바뀝니다 — 재 봤습니다.** 이전 도구의 144개 조합 격자에서도, 월급·인플레·증자율·뉴스 세기·봇 구성·호가폭을 더 넓게
흔든 이번 탐색에서도 막사기가 중앙값(16.5등) 아래로 내려간 파라미터 조합은 없었습니다. 가장 멀리 간 조합(월급 2만·가치봇 40%·종목 변동성 0.8·
뉴스 충격 0.20/0.15)이 막사기 7.9등이었는데 그 대신 몰빵이 5.1등으로 올라왔고, 월급을 5분에 한 번·증자 2%·호가폭 2%로 두면
막사기 11.0등·몰빵 13.3등에서 멈추면서 유능도 11.3등으로 같이 밀렸습니다. 증자 상한을 2%나 0%로 낮춰도 등수 관계는 그대로였습니다 —
수익률 숫자만 같이 줄어듭니다. 종목마다 숨은 추세를 넣는 메커니즘(적정가에 종목별 기울기)도 검토했지만 막사기를 중앙값 아래로 내리지 못했고
매도 호가 공백만 커졌습니다. 이건 "현금은 손해"라는 설계 의도의 귀결입니다.

**바꾸려면 경제를 바꿔야 하고, 그 묶음이 `PRESETS.marketMaker` 입니다.** 기본값은 끔이고, 방을 만들 때 설정에 펼쳐 넣거나
`node tools/balance.js --preset marketMaker` 로 잽니다. 내용은 다섯 가지입니다.

1. **시장조성자** — 공모에서 안 팔린 실권주를 들고 적정가(지연 기준가) ±0.5%에 양방향 호가를 대는 시스템 참가자(순위·월급·참가자 수 제외).
   시세는 이 밴드 안에서만 움직이고 종목 간 차이는 뉴스로만 생깁니다. 매도 호가 공백 49% → 0.2%. 발행 시가총액 300%로 실권주가 바닥나지 않게 합니다.

4. **뉴스를 키움** — 적정가 충격 ±25%, 45초 간격, 봇 인지 시차 최대 120초, 효력 180초. 종목 개별 잡음은 0.02로 줄여
   '최근 1분 상승'이 잡음이 아니라 진행 중인 뉴스가 되게 합니다.
5. 호가 제시형 봇의 사다리를 2단계·0.3%로 좁혀 시장조성자 밴드 안에 넣습니다.

**이 프리셋의 대가 — 그래서 기본값으로 켜지 않았습니다.**
- **시세를 참가자가 아니라 적정가가 정합니다.** 시장조성자가 적정가로의 수렴을 보장하므로 화면의 괴리율이 확정 수익 신호가 됩니다.
  '적정가보다 싼 매도 호가면 사고 적정가보다 비싼 매수 호가면 판다'만 2초마다 반복하는 전략을 섞어 재면(39명·24회·시드 90000)
  3.1등에 24판 중 17판 1위입니다(뉴스 대응 9.7등·유능 9.7등) — 기본 경제에서는 같은 전략이 13.5등, 1위 5판입니다.
  화면에 '괴리율순' 정렬이 있으니 실제 참가자도 할 수 있습니다.
  "정답을 알아도 현재가는 적정가에서 벌어지고 그 괴리가 눈치싸움의 재료"라는 설계 철학과 어긋납니다.
- **빠른 추격과 뒷북의 차이가 사라집니다** — 어느 구성에서도 유의하지 않고, 시드 31337에서는 뒷북 8.9등 vs 추격 12.7등으로 뒷북이 앞섭니다.
  선점 보상 곡선도 완만합니다: 뉴스 대응을 0·3·10·30·60초 늦추면 수익률 26.1 · 25.9 · 28.0 · 24.7 · 24.8%로 60초 늦어야 1.2%p 차이입니다
  (기본 경제 4.9%p). 기준가 시정수(`marketMaker.lagSec`)를 120초로 줄이면 2.8%p, 60초면 14.5%p로 가팔라지지만
  120초는 몰빵이 16.4등(시드 90000), 60초는 전액 투자가 16.0·16.2등(시드 4242·31337)으로 중앙값 위로 올라옵니다.
- **내린 판에서는 무행동이 올라옵니다.** 뉴스 호재:악재가 5:5라 판마다 시장 방향이 갈립니다. 4종목 방(시드 90000)은 평균 주가 −1.6%에 무행동 23.5등,
  33명 시드 777은 25.9등(기준 24.75)으로 아슬아슬합니다. 호재 비율을 0.55로 올리면 무행동이 28~30등(55명 47등)으로 내려가지만
  시드 777에서 유능 9.1등·전액 16.3등이 되고, 0.6은 세 구성에서 몰빵·전액이 중앙값 위로 올라와서 5:5로 뒀습니다.
- 전액 투자는 중앙값 근처입니다(봇 50·시드 90000에서 16.3등, 중앙값 16.5). 8종목·봇 60 방은 유능 8.8등·몰빵 16.4등·전액 14.9등,
  10분 방은 전액 15.4등으로 판정이 흔들립니다.
- 무상증자 팝업이 사라집니다. 월급 팝업은 남습니다.
- 여기까지 오며 버린 변형: 현금 이자 0.2%/분에 인플레 0은 시장이 안 오른 판에서 무행동이 24.3등(시드 777)·23.7등(4종목)·40.4등(55명)까지 올라왔고,
  인플레 0.2%는 무행동 25.0등(777)으로 경계선, 0.5%는 유능이 8.5등(4242)으로 밀렸습니다. 무상증자를 1%만 켜도 몰빵 15.9등, 2%면 전액 13.7등으로
  다시 중앙값 위입니다. 시초가 프리미엄 20%는 무행동 24.5등(777)입니다. 평가를 최우선 매수호가로 바꾸는 것은 등수를 바꾸지 않아 뺐습니다.


**균등 지급은 절대 순위를 바꾸지 못합니다.** 전원이 같은 자산으로 출발하고 주식 총공급이 고정이면,
아무것도 하지 않은 사람의 최종 자산은 **정확히 시장 평균**이 됩니다. 월급을 3배로 올려도 똑같습니다.
그래서 시작 주식을 0으로 두고 공모로만 주식을 얻게 만들었습니다.
이 변경으로 무행동자가 중위권(평균)에서 최하위권으로 내려갑니다.

**현금만 늘리면 호가창이 무너집니다.** 월급으로 현금을 넣으면서 주식 공급을 고정하면
전원이 매수만 하게 되어 매도 호가가 전체 시간의 85% 동안 비었습니다.
무상증자로 현금 증가분만큼 주식도 늘리자 그 비율이 17%로 떨어지고 체결량이 6.7배가 됐습니다.

**인플레이션은 밸런스를 바꾸지 않습니다.** 0%든 10%든 무행동자 등수, 체결가 변동, 체결량,
호가 균형이 전부 같았습니다. 적정가가 오르는 것이 실제 체결가로 전달되는 통로가 `value` 봇
하나뿐이라(기본 비중 2%, 봇 50명 중 1명) 시장을 움직이지 못합니다.
5%/분으로 두면 적정가만 +117% 떠내려가고 체결가는 +9.6%만 올라 전 종목이 영구 저평가로 표시됩니다.
그래서 적정가가 실제 가격 경로를 따라가는 값(0.5%/분)으로 낮췄습니다.
이러면 괴리율이 "이 종목이 지금 비싼가"라는 쓸모 있는 신호가 됩니다.
"가만히 있으면 손해"는 인플레가 아니라 초기 주식 0 + 개장 공모 구조가 만듭니다.

**돌발뉴스가 "빠른 대응이 보상받는" 구조를 만듭니다.** 차트 모멘텀만으로는 적극적 매매가
그냥 보유를 이기지 못했지만, 뉴스라는 명확한 신호가 생기자 뉴스에 먼저 반응한 쪽이
통계적으로 유의하게 앞섰습니다. 봇이 뉴스를 즉시가 아니라 시차를 두고 인지하도록 만든 게 핵심입니다.
봇이 전부 즉시 반응하면 사람은 항상 마지막 매수자가 되어 손해만 봅니다.

**주문을 어떻게 내느냐가 결과를 가릅니다.** 뉴스에 소극적 지정가(현재가)로 대응하면
즉시 체결률이 23%에 그쳐 현금이 호가에 묶이고, 그 상태로 인플레이션을 맞아 24명 중 15.1등이 됐습니다.
현재가보다 2% 높게 지르면 체결률 67%, 성적 5.3등으로 뒤집힙니다.
뉴스 토스트의 "바로 매수/매도" 단추는 운영자 요청으로 뺐습니다. 지금은 종목 화면의 호가 사다리에서 현재가보다 위 칸을 눌러 같은 주문을 냅니다.

**선점 경쟁이 성립하려면 매도 물량이 있어야 합니다.** 초기 설계에서는 시중 현금이 주식 총액의
2.6배였습니다. 매도 호가에 쌓인 금액이 종목당 47만원인데 1인당 현금은 209만원이라,
한 명이 현금의 45%만 써도 매도 물량 전체를 긁어버려 두 번째 사람은 살 게 없었습니다.
늦은 사람이 "비싸게 사는" 게 아니라 "아예 못 사는" 상태였고, 그건 눈치싸움이 아니라 먹통입니다.

`ipoBidRatio` 를 10%에서 30%로 올려 공모에서 현금을 주식으로 전환시키자
매도호가 47만 → 260만, 매수호가 385만 → 172만으로 역전됐습니다.
20명 동시 매수 체결률이 6% → 21%, 가격 임팩트가 +2.2% → +7.1% 가 됐습니다.
`makerLevels` 4단계 사다리도 같은 목적입니다 — 늦은 사람도 체결은 되되 위로 갈수록 비싸집니다.

차트 모멘텀(빠른 추격)이 보유를 이기는 항목은 발행 시가총액을 150%로 올린 뒤에야 전 인원에서 통과했습니다.
더 강하게 만들려면 `maxBonusRate` 를 낮추거나(무상증자가 보유를 보상한다) `lookbackSec` 를 늘리면 됩니다.
