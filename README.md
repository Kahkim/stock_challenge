# 모의주식 챌린지

참가코드 하나로 모여서 10~20분 동안 모의 주식을 사고파는 실시간 웹 게임.
최종 자산이 가장 높은 사람이 이깁니다.

이 저장소는 **서버(게임 엔진 + API)** 입니다. 화면은 별도로 개발 중이며,
서버와의 계약은 [`docs/API.md`](docs/API.md) 에 전부 정리돼 있습니다.

```bash
node server.js            # http://localhost:3000
npm test                  # 엔진 21 + API 23 = 44개 테스트
node tools/balance.js     # 설정을 바꾼 뒤 밸런스가 깨지지 않았는지 측정
```

외부 의존성이 없습니다. Node 18 이상이면 그대로 돌아갑니다.

---

## 게임 구조

```
로비 → 개장 공모(45초) → 정규장(15분) → 마감
```

- **시작 자산은 현금 100만원뿐입니다.** 주식은 0주로 시작합니다.
- **개장 공모**에서 가격과 수량을 써내면 단일가로 시초가가 정해지고 주식이 배정됩니다.
  시초가는 설정값이 아니라 **참가자들의 청약 결과**로 만들어집니다.
- 매분 **월급**(현금)이 들어오고, 동시에 주식 보유자에게만 **무상증자**가 배정됩니다.
- 매분 전 종목의 **적정가**가 조금씩 오릅니다(인플레이션). 현금은 액수가 그대로라 상대적으로 가치가 떨어집니다.
- 거래는 실제 증권시장과 같은 **연속경쟁매매**(가격 우선 → 시간 우선)입니다.
- 평균 70초마다 **돌발뉴스**(호재/악재)가 터지고, 봇들이 **시차를 두고** 동조합니다.

## 설정

전부 `src/config.js` 의 기본값이고, 방을 만들 때 화면에서 덮어쓸 수 있습니다.

| 항목 | 기본값 |
|---|---|
| 종목 | 10종목 풀에서 선택 (기본 6종목) |
| 시드머니 | 1,000,000원 |
| 시작 주식 | 0주 |
| 월급 | 100,000원 / 1분 |
| 인플레이션 | 0.5% / 1분 (적정가 상승 방식) |
| 무상증자 | 1회 최대 5% |
| 정규장 | 15분 |
| 개장 공모 | 45초 |
| 최소 거래 단위 | 10주 |
| 호가 단위 | 2,000원 미만 5원 / 5,000원 미만 10원 / 그 이상 25원 |
| 수수료 | 편도 0.15% |
| NPC 봇 | 30명 (순위에서는 제외) |
| 돌발뉴스 | 평균 70초 간격, 호재:악재 = 5:5, 효력 90초 |
| 공모 청약 비중 | 봇이 현금의 30%부터 청약 (시장에 풀리는 주식량을 정한다) |
| 호가 사다리 | 호가 제시형 봇이 4단계에 걸쳐 호가를 깐다 |

종목을 바꾸려면 `src/config.js` 의 `STOCK_POOL` 만 고치면 됩니다.

## NPC 봇

봇은 **사람과 완전히 동일한 조건**으로 참가합니다. 같은 시드머니, 같은 월급, 같은 인플레이션을 받고,
사람 화면에 보이는 정보(현재가·적정가·최근 추세·자기 잔고)만 봅니다.
남의 미체결 주문이나 보유내역은 보지 않습니다 — 서버가 볼 수 있다고 해서 보여주면
봇이 구조적 내부자가 되고 게임의 정당성이 무너집니다.

시장의 성격은 봇 한 명의 알고리즘이 아니라 **봇 집단의 성향 구성비**로 조절합니다.

| 성향 | 기본 비중 | 하는 일 |
|---|---|---|
| `trend` | 60% | 오른 종목에 올라탄다 — 시장에 모멘텀을 만든다 |
| `maker` | 20% | 종목 견해 없이 양방향 호가를 낸다 — 호가창이 한쪽만 차는 걸 막는다 |
| `noise` | 15% | 봇마다 고정된 무작위 취향 |
| `contra` | 3% | 내린 종목을 줍는다 — 버블이 무한히 커지지 않게 잡는다 |
| `value` | 2% | 적정가 대비 싼 종목을 산다 — 인플레이션을 체결가로 전달한다 |

`lookbackSec`(기본 120초)이 가장 중요한 다이얼입니다. 봇이 추세를 판단하는 창인데,
길수록 봇이 느리게 반응해서 짧은 창을 보는 사람이 **먼저** 올라탈 수 있습니다.
30초로 줄이면 봇이 사람보다 빨라져 추격매매가 오히려 손해가 됩니다.

## 구조

```
server.js            HTTP + SSE. 라우팅과 인증만 담당
src/config.js        모든 기본값과 종목 풀
src/orderbook.js     연속경쟁매매 오더북 (가격 우선 → 시간 우선)
src/game.js          게임 엔진 — 공모, 체결 정산, 월급, 증자, 인플레이션, 순위
src/bots.js          NPC 참가자 의사결정
src/rooms.js         방 관리, 참가코드, 설정값 검증
tests/               엔진 테스트 21개, API 테스트 23개
tools/balance.js     밸런스 측정 도구
docs/API.md          화면 개발용 API 전체 명세
```

## 밸런스에 관한 기록

설계값은 감이 아니라 측정으로 정했습니다. 특히 다음 두 가지는 시뮬레이션으로 확인된 사실입니다.

**균등 지급은 절대 순위를 바꾸지 못합니다.** 전원이 같은 자산으로 출발하고 주식 총공급이 고정이면,
아무것도 하지 않은 사람의 최종 자산은 **정확히 시장 평균**이 됩니다. 월급을 3배로 올려도 똑같습니다.
그래서 시작 주식을 0으로 두고 공모로만 주식을 얻게 만들었습니다.
이 변경으로 무행동자가 중위권(평균)에서 최하위권으로 내려갑니다.

**현금만 늘리면 호가창이 무너집니다.** 월급으로 현금을 넣으면서 주식 공급을 고정하면
전원이 매수만 하게 되어 매도 호가가 전체 시간의 85% 동안 비었습니다.
무상증자로 현금 증가분만큼 주식도 늘리자 그 비율이 17%로 떨어지고 체결량이 6.7배가 됐습니다.

**인플레이션은 밸런스를 바꾸지 않습니다.** 0%든 10%든 무행동자 등수, 체결가 변동, 체결량,
호가 균형이 전부 같았습니다. 적정가가 오르는 것이 실제 체결가로 전달되는 통로가 `value` 봇
하나뿐이라(기본 비중 2%, 봇 50명 중 1명) 시장을 움직이지 못합니다.
5%/분으로 두면 적정가만 +117% 떠내려가고 체결가는 +9.6%만 올라 전 종목이 영구 저평가로 표시됩니다.
그래서 적정가가 실제 가격 경로를 따라가는 값(0.5%/분)으로 낮췄습니다.
이러면 괴리율이 "이 종목이 지금 비싼가"라는 쓸모 있는 신호가 됩니다.
"가만히 있으면 손해"는 인플레가 아니라 초기 주식 0 + 개장 공모 구조가 만듭니다.

**돌발뉴스가 "빠른 대응이 보상받는" 구조를 만듭니다.** 차트 모멘텀만으로는 적극적 매매가
그냥 보유를 이기지 못했지만, 뉴스라는 명확한 신호가 생기자 뉴스에 먼저 반응한 쪽이
통계적으로 유의하게 앞섰습니다. 봇이 뉴스를 즉시가 아니라 시차를 두고 인지하도록 만든 게 핵심입니다.
봇이 전부 즉시 반응하면 사람은 항상 마지막 매수자가 되어 손해만 봅니다.

**주문을 어떻게 내느냐가 결과를 가릅니다.** 뉴스에 소극적 지정가(현재가)로 대응하면
즉시 체결률이 23%에 그쳐 현금이 호가에 묶이고, 그 상태로 인플레이션을 맞아 24명 중 15.1등이 됐습니다.
현재가보다 2% 높게 지르면 체결률 67%, 성적 5.3등으로 뒤집힙니다.
화면의 "즉시 매수" 버튼은 편의 기능이 아니라 밸런스의 일부입니다.

설정을 바꾼 뒤에는 `node tools/balance.js` 로 다시 재보세요. 여섯 가지를 판정합니다.
평균 차이의 유의성은 표준편차가 아니라 **표준오차**로 봅니다.

```
[사람 전략별 평균 등수]  (24명 중, 40회 측정)
  뉴스 대응 (발생 2초 뒤)      6.9등  ±0.48
  공모 후 보유                8.3등  ±0.33
  빠른 추격 (10초창)           8.7등  ±0.61
  역추세                     11.3등  ±0.68
  뒷북 추격 (60초창)          17.3등  ±0.42
  무행동                     22.5등  ±0.00

✓ 가만히 있으면 확실히 하위권
✓ 호가창 양쪽이 대체로 채워진다          매도 호가가 비는 시간 28.4%
✓ 종목 선택이 결과를 가른다              종목 간 격차 15.4%
✓ 돌발뉴스에 빠르게 반응하면 유리        6.9등 vs 보유 8.3등
✓ 뒷북보다 먼저 잡는 게 유리             8.7등 vs 뒷북 17.3등
✓ 오르는 종목에 먼저 올라타는 게 보유보다 유리   추격 8.3등 vs 보유 9.8등
```

**선점 보상.** 같은 뉴스에 즉시 반응한 사람과 60초 뒤에 반응한 사람의 최종 자산 차이는 **30.7%** 입니다.
처음 3초가 가장 크고(30.7% → 23.8%), 30초를 넘기면 거의 남지 않습니다(4.9%).

```
   0초 뒤   4,008,868원   +30.7%    5.7등 / 24명
   3초 뒤   3,798,271원   +23.8%    9.1등
   8초 뒤   3,690,630원   +20.3%   11.4등
  15초 뒤   3,579,290원   +16.7%   12.0등
  30초 뒤   3,217,241원   + 4.9%   17.5등
  60초 뒤   3,068,141원   + 0.0%   19.3등
```

**선점 경쟁이 성립하려면 매도 물량이 있어야 합니다.** 초기 설계에서는 시중 현금이 주식 총액의
2.6배였습니다. 매도 호가에 쌓인 금액이 종목당 47만원인데 1인당 현금은 209만원이라,
한 명이 현금의 45%만 써도 매도 물량 전체를 긁어버려 두 번째 사람은 살 게 없었습니다.
늦은 사람이 "비싸게 사는" 게 아니라 "아예 못 사는" 상태였고, 그건 눈치싸움이 아니라 먹통입니다.

`ipoBidRatio` 를 10%에서 30%로 올려 공모에서 현금을 주식으로 전환시키자
매도호가 47만 → 260만, 매수호가 385만 → 172만으로 역전됐습니다.
20명 동시 매수 체결률이 6% → 21%, 가격 임팩트가 +2.2% → +7.1% 가 됐습니다.
`makerLevels` 4단계 사다리도 같은 목적입니다 — 늦은 사람도 체결은 되되 위로 갈수록 비싸집니다.

마지막 항목은 달성하지 못했습니다. **뉴스 없이 차트 모멘텀만으로는** 적극적 매매가
그냥 들고 있는 것을 안정적으로 이기지 못합니다. 실제 게임에서는 뉴스가 신호 역할을 하므로
큰 문제는 아니지만, 더 강하게 만들려면 `maxBonusRate` 를 낮추거나(무상증자가 보유를 보상한다)
`lookbackSec` 를 늘리면 됩니다. 둘 다 호가창 균형과 상충하니 바꾼 뒤 반드시 다시 재세요.
