# 주요 화면 설계 — 모바일

5~10분짜리 실시간 모의투자 대결 게임의 주요 화면 3장에 대한 설계 문서.

비주얼 시안: `design/artboards/*.dc.html`
(`node design/gen.mjs` 로 재생성, Claude Design 캔버스로 발행됨)

---

## 0. 전제

### 확정된 것 (요구자 확인)

| 항목 | 값 |
| --- | --- |
| 시세/체결 방식 | **내부 시뮬레이션 거래소.** 참가자 주문과 봇 유동성이 실제로 호가창을 형성하고 체결된다. 참가자의 매매가 가격에 영향을 준다. |
| 한 판 길이 | **5~10분** |
| 플랫폼 | 모바일 웹/앱 (390 × 844 기준) |

### 이 문서에서 제안하는 기본값 (미확정, 검토 필요)

레포에 기존 결정 기록이 없어 아래 값은 설계를 진행하기 위해 **제안**한 것이다.
확정된 사실이 아니므로 그대로 구현하기 전에 합의가 필요하다.

| 항목 | 제안값 | 근거 |
| --- | --- | --- |
| 시작 자금 | 1,000만원 (100만 / 1,000만 / 1억 중 선택) | 호가 단위·수수료가 체감되면서 계산이 쉬운 자릿수 |
| 종목 수 | 8종목 (풀 12종목 중 방장이 선택) | 5분 안에 전부 훑어볼 수 있는 상한. 12개는 리스트가 한 화면을 넘어감 |
| 참가 인원 | 2~8명 | 순위 리스트가 스크롤 없이 들어가는 상한 |
| 호가 단위 | KRX 관례 준용 (5,000~20,000원 → 10원) | 실제 감각 유지 |
| 등락 색상 | 상승 = 빨강 / 하락 = 파랑 (한국 관례) | 국내 사용자 기준. 글로벌 관례(상승=초록)와 반대이므로 설정으로 뺄지 결정 필요 |
| 종목명 | 전부 가상 (서진해운, 누리에너지 등) | 내부 시뮬레이션이라 실제 종목 시세와 무관. 실제 종목명을 쓰면 오해 소지 |

## 1. 화면 구조 (IA)

```
[방 만들기] ──(초대코드)──> [대기실*] ──(방장 시작)──> [전체 시황] <──> [개별 종목]
                                                          │
                                                          └──> [정산 결과*]
```

`*` 이번 시안 범위 밖. 별도 설계 필요.

게임 중 하단 탭: `시황` / `내 자산` / `방 정보`
개별 종목 화면은 시황의 종목 행을 눌러 **푸시**되는 화면 (탭이 아님).

---

## 2. 화면 1 — 방 만들기

**목적**: 방장이 한 판의 규칙을 정하고 초대코드를 만든다. 게임 시작 전 유일한 설정 지점.

| 블록 | 컨트롤 | 비고 |
| --- | --- | --- |
| 방 이름 | 텍스트 입력 (20자) | 참가자가 초대코드로 들어올 때 확인용 |
| 한 판 시간 | 세그먼트 `5분 / 7분 / 10분` | 확정 범위. 이 값이 차트 봉 단위와 순위 갱신 주기를 결정 |
| 시작 자금 | 세그먼트 `100만 / 1,000만 / 1억` | 전원 동일 |
| 거래 종목 | 칩 다중 선택, 12개 중 8개 | 선택 수를 헤더에 표시 (`8 / 12 선택`) |
| 시장 변동성 | 세그먼트 `잔잔 / 보통 / 폭풍` | 봇 유동성 공급량 + 돌발 뉴스 횟수 + 목표 변동폭을 한 번에 바꾸는 프리셋 |
| 규칙 | 토글 3개 | 공매도 허용 / 순위 실시간 공개 / 돌발 뉴스 |
| 참가 인원 | 스테퍼 (2~8) | |
| CTA | `방 만들고 초대코드 받기` | 누르면 6자리 코드 발급 → 대기실 |

**설계 판단**

- 설정을 한 화면에 다 넣었다. 5분짜리 게임을 만드는 데 위저드 3단계를 태우면 배보다 배꼽이 크다.
- "시장 변동성"은 봇 유동성/뉴스/변동폭을 개별 노출하지 않고 프리셋 하나로 묶었다.
  세부 튜닝이 필요하면 `고급 설정` 접힘 영역으로 빼는 것을 권장.
- 방을 만든다고 장이 열리지는 않는다. 방장이 대기실에서 시작을 눌러야 한다 (지각자 대응).

## 3. 화면 2 — 전체 시황

**목적**: 한 판의 상황판. "지금 뭐가 뛰고 있나"와 "내가 몇 등인가" 두 가지를 한 화면에서 본다.

### 구성

1. **게임 헤더** (sticky)
   - 방 이름, `LIVE` 배지, 갱신 주기 표시
   - 남은 시간 `03:42` (mono, 34px) + 진행 바
   - 진행 바는 경과 비율. 마지막 60초에 색을 바꿔 종료 임박을 알리는 것을 권장.
2. **내 자산 카드**
   - 총자산 / 손익액 / 손익률 / 순위 배지
   - 현금 · 평가금액 · 실현손익 3분할
   - **실현손익을 노출하는 이유**: 총자산만 보이면 "왜 줄었지"를 설명할 수 없다.
     평가금액 + 현금 = 총자산, 실현손익 + 평가손익 = 총손익이 화면에서 검산돼야 한다.
3. **전체 종목 리스트** (8행)
   - 순번 · 종목명 · 섹터 · 스파크라인 · 현재가 · 등락률
   - 정렬: `등락률순` (기본) / `거래대금순`
   - 스파크라인은 판 시작(기준가) 이후 전체 경로. 축·눈금 없음 — 방향만 읽는 용도.
4. **자산 순위** (참가자 수만큼)
   - 순위 배지 · 닉네임 · 총자산 · 수익률
   - 내 행은 배경 틴트 + 좌측 액센트 바 + `나` 태그로 고정 강조
   - 방 설정에서 "순위 실시간 공개"를 끄면 이 섹션은 종료 시까지 잠금 처리
5. **하단 탭바**

### 설계 판단

- 시황과 순위를 탭으로 나누지 않고 한 화면에 세로로 쌓았다.
  5분짜리 게임에서 탭 전환은 정보를 감추는 비용이 크다.
- 순위 리스트에 "보유 종목"은 넣지 않았다. 남의 포지션이 보이면 게임이 아니라 복사가 된다.
  공개 여부는 정책 결정 사항 (미결정 참조).

## 4. 화면 3 — 개별 종목

**목적**: 한 종목을 보고 주문을 낸다. 내부 거래소이므로 **호가창이 곧 다른 참가자들의 의사표시**다.

### 구성

1. **헤더**: 뒤로 · 종목명 · 섹터 칩 · 남은 시간(축소)
2. **가격 블록**: 현재가(32px) · 전일대비 · 등락률 / 우측에 고가·저가·거래량
   - "전일"이 없는 게임이므로 기준은 **판 시작가**. 표기는 `기준가` 로 통일.
3. **차트**: 캔들 + 거래량 바
   - 시간 단위 칩: `1초 / 5초 / 30초 / 전체` (기본 5초)
   - 기준가 수평선 + 라벨을 항상 표시 (플러스인지 마이너스인지가 최우선 정보)
4. **호가창** — 매도 5호가 / 스프레드 / 매수 5호가
   - 3열 구조 `매도잔량 | 호가 | 매수잔량` (국내 앱 관례)
   - 잔량 막대는 표시된 10호가 중 최대 잔량 기준 상대 폭
   - 각 호가에 기준가 대비 등락률 병기
   - **내 지정가 주문은 해당 호가 행에 `내 200` 배지로 표시** — 내부 거래소에서만 가능한 정보이고,
     "내 주문이 아직 안 붙었다"를 확인하는 유일한 수단이므로 필수
   - 하단에 총매도잔량 / 총매수잔량
5. **내 포지션**: 보유 수량 · 평단 · 평가손익
6. **주문 패널** (하단 고정)
   - `지정가 / 시장가` 탭
   - 가격 스테퍼 (호가 단위로 증감) · 수량 스테퍼
   - 비율 칩 `10% / 25% / 50% / 최대 N주`
   - 주문금액, 주문가능 현금 및 최대 수량
   - `매도`(파랑) / `매수`(빨강) 버튼

### 설계 판단

- 호가창 행 높이 44px. 국내 실제 앱은 28~32px로 더 조밀하지만,
  모든 호가가 탭 대상(누르면 주문가에 반영)이므로 최소 터치 영역을 지켰다.
  10호가로 늘리면 20행 = 880px이 되어 화면을 넘어가므로 **5호가 고정 + 접힘 확장**을 권장.
- 주문 패널을 바텀시트가 아닌 인라인 고정으로 뒀다.
  5분 안에 수십 번 주문하는 게임에서 시트 열고 닫기는 명백한 마찰.
- 매수 = 빨강, 매도 = 파랑. 등락 색상과 같은 규칙을 쓴다.

## 5. 갱신 주기 — "10초 단위가 적당한가?"

**결론: 10초는 이 게임에 너무 느리다.**

7분(420초) 한 판 기준으로 10초 갱신은 판 전체에서 **가격이 42번밖에 안 움직인다**.
플레이어 입장에선 사실상 정지 화면이고, 종료 직전 순위 역전을 놓친다.
또한 내부 시뮬레이션 거래소에서는 내 주문이 체결됐는지를 10초 뒤에 아는 셈이 되는데,
이건 게임이 아니라 지연이다.

### 제안하는 주기

| 데이터 | 주기 | 방식 | 근거 |
| --- | --- | --- | --- |
| 호가창 · 체결 | 이벤트 발생 시 즉시, 클라이언트에서 **250ms 스로틀** | WebSocket push | 내부 거래소이므로 체결 이벤트가 곧 진실. 250ms보다 빠르면 사람이 못 읽는다 |
| 차트 | 서버가 **1초 틱** OHLC 생성, 기본 **5초봉** 집계 | 봉 확정 시 push + 진행 중 봉은 현재가로 갱신 | 7분 = 5초봉 84개. 캔들차트로 읽기 적당한 밀도 |
| 전체 종목 등락 | **1초** 스냅샷 브로드캐스트 | 8종목 × (현재가, 등락률, 스파크 1포인트) ≈ 200B/초 | 리스트가 살아 움직여야 "시황"이다 |
| 참가자 자산 순위 | **2초** 서버 집계 후 브로드캐스트 | N명 × 보유 종목 평가 계산이 필요하므로 종목 시세보다 한 단계 느리게 | 순위는 1초마다 안 바뀐다. 2초면 역전 순간을 놓치지 않는다 |
| 남은 시간 | 클라이언트 로컬 카운트다운, **5초마다** 서버 시각 동기화 | | 타이머를 push로 받을 이유가 없다 |

시간 단위 칩(`1초 / 5초 / 30초`)이 의미 있으려면 서버가 **1초 틱을 원본으로 저장**해야 한다.
5초봉을 원본으로 저장하면 1초봉으로 되돌릴 수 없다.

### 10초가 맞는 유일한 경우

한 판을 **며칠 단위 리그**로 바꾼다면 10초(혹은 그 이상)가 맞다.
현재 확정된 5~10분 세션에서는 아니다.

## 6. 비주얼 시스템

레포에 기존 디자인 시스템이 없어 새로 정의했다.

| 항목 | 값 |
| --- | --- |
| 배경 | `#0A0C10` / 서피스 `#12151B` `#191D25` `#20252E` |
| 경계선 | `#242A34` `#2E3540` |
| 텍스트 | `#EDEFF3` / 보조 `#8B93A1` / 약함 `#5C6472` |
| 상승 | `#FF4D5E` |
| 하락 | `#4C8DFF` |
| 액센트 (CTA·타이머·내 항목) | `#C6F24E` |
| 본문 폰트 | IBM Plex Sans KR |
| 숫자 폰트 | IBM Plex Mono (`tabular-nums`) |
| 최소 터치 영역 | 44px |
| 라운드 | 8 / 11 / 12 / 14px |

- 다크 기본. 숫자가 주인공인 화면이고, 빨강/파랑 대비가 어두운 바탕에서 가장 정확하게 읽힌다.
- 액센트 라임은 **게임성(타이머, 내 순위, 주 CTA)에만** 쓴다. 시세 색과 절대 섞지 않는다.
- 모든 수치는 mono + tabular-nums. 1초마다 갱신되는 숫자가 자리를 흔들면 안 된다.

## 7. 미결정 사항

구현 전에 정해야 하는 것들. 이 문서는 답을 갖고 있지 않다.

**거래소 규칙**
- 체결 우선순위: 가격 우선 → 시간 우선으로 갈 것인가
- 봇 유동성 모델: 어떤 알고리즘이 호가를 대는가, 참가자 물량을 다 받아주는가
- 시장가 주문의 슬리피지 상한
- 상·하한가(±30%) 적용 여부
- 종목별 총 유동 주식 수 (한 명이 전량 사버리는 것을 막을 상한)
- 수수료/세금 반영 여부

**게임 규칙**
- 남의 보유 종목 공개 여부
- 도중 이탈/재접속 처리
- 동점 처리
- 돌발 뉴스의 형태 (전체 공지인가, 종목별인가, 미리 보이는가)

**화면**
- 대기실 화면
- 정산 결과 화면 (한 판이 끝나는 게임인데 결과 화면이 없다)
- 내 자산 탭 (보유 종목 목록 + 체결 내역)
- 등락 색상 반전 설정 (글로벌 관례 사용자 대응)
