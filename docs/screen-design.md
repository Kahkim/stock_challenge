# 주요 화면 설계 — 모바일

5~10분짜리 실시간 모의투자 대결 게임의 주요 화면 설계.

비주얼 시안: `design/artboards/*.dc.html`
(`node design/gen.mjs` 로 재생성, Claude Design 캔버스로 발행됨)

---

## 0. 전제

### 확정된 것 (요구자 확인)

| 항목 | 값 |
| --- | --- |
| 시세/체결 방식 | **내부 시뮬레이션 거래소.** 참가자 주문과 봇 유동성이 실제로 호가창을 형성하고 체결된다. 참가자의 매매가 가격에 영향을 준다. |
| 한 판 길이 | **5~10분** |
| 플랫폼 | 모바일 웹/앱 (390 × 844 기준) |
| 참가 설정 | 사람 수는 설정하지 않는다. 방장은 **봇 수**만 정하고, 사람은 초대코드로 들어온 만큼 참가한다. |
| 돌발 뉴스 | **팝업**으로 알린다 |
| 월급 | **매 1분** 지급 |
| 인플레이션 | **매 1분** 현금이 줄어들고, 자산 화면에 반영한다 |

### 미확정 — 값이 필요함

**거래 종목 10개 목록.** 요구자가 제안한 10개 종목이 있으나 이 문서를 쓰는 시점에
대화·레포·이슈 어디에도 기록이 없다. 현재 시안의 종목명(서진해운, 누리에너지 등)은
**전부 자리표시용 가상 종목**이며, 목록을 받는 대로 교체해야 한다.
`design/gen.mjs` 의 `TICKERS` 배열과 `stocks` 배열 두 곳이다.

### 이 문서에서 제안하는 기본값 (검토 필요)

| 항목 | 제안값 | 근거 |
| --- | --- | --- |
| 시작 자금 | 1,000만원 (100만 / 1,000만 / 1억 중 선택) | 호가 단위·수수료가 체감되면서 계산이 쉬운 자릿수 |
| 월급 | 300,000원 / 분 | 아래 "분당 정산" 참조 — 인플레와 상쇄되도록 잡았다 |
| 인플레 | 현금의 3% / 분 | 위와 같음 |
| 종목 수 | 8종목 (풀에서 방장이 선택) | 5분 안에 전부 훑어볼 수 있는 상한 |
| 봇 수 | 8 (0~20) | 8종목 호가창이 비어 보이지 않을 최소선 |
| 호가 단위 | KRX 관례 준용 (5,000~20,000원 → 10원) | 실제 감각 유지 |
| 등락 색상 | 상승 = 빨강 / 하락 = 파랑 (한국 관례) | 국내 사용자 기준 |

## 1. 화면 구조 (IA)

```
[방 만들기] ──(초대코드)──> [대기실*] ──(방장 시작)──> [전체 시황] <──> [개별 종목]
                                                          │              │
                                                          └──> [정산 결과*]
                                     (오버레이) [돌발 뉴스 팝업] [월급 입금 팝업]
```

`*` 이번 시안 범위 밖. 별도 설계 필요.

팝업 두 종류는 독립 화면이 아니라 **어느 화면 위에서든 뜨는 오버레이**다.
시안에서는 각각 전체 시황 / 개별 종목 위에 얹은 상태로 그렸다.

게임 중 하단 탭: `시황` / `내 자산` / `방 정보`

## 2. 분당 정산 — 월급과 인플레

한 판 동안 매 1분 경계에서 두 가지가 동시에 일어난다.

```
매 1분:   현금 += 월급(300,000)
          현금 -= floor(현금 × 인플레율(3%))      ← 월급 지급 후의 잔액이 기준
```

### 왜 이 값인가

**인플레율 × 시작자금 = 월급** 이 되도록 잡았다 (10,000,000 × 3% = 300,000).
그래서:

- 현금을 100% 들고 가만히 있으면 월급과 인플레가 **정확히 상쇄**된다 → 본전
- 주식에 넣어두면 인플레 대상 현금이 줄어드는 만큼 월급이 순증한다 → 앞선다
- 현금을 쌓아두는 플레이는 자동으로 손해가 된다

인플레는 **현금에만** 붙는다. 평가금액에는 붙지 않는다. 이게 현금 회피 압력의 전부다.
시작 자금을 바꾸면 월급도 같이 바뀌어야 이 관계가 유지된다.

### 수익률 기준이 바뀐다

월급이 전원에게 똑같이 들어오므로, 수익률을 시작 자금 기준으로 계산하면
시간이 갈수록 **전원의 수익률이 같이 부풀어 오른다** — 실력을 나타내지 못한다.

그래서 화면의 수익률은 전부 **누적 투입** 기준이다.

```
누적 투입 = 시작 자금 + 지금까지 받은 월급 총액
수익률    = (총자산 − 누적 투입) / 누적 투입
```

인플레로 깎인 금액은 누적 투입에서 빼지 않으므로, 이 수익률은
"인플레를 이겼는가"까지 포함한 실질 성과가 된다.

### 시안에 쓰인 원장 (검산용)

시안의 "나"는 경과 3분 2초 시점이고, 화면의 모든 금액은 아래에서 나온다.

| 시각 | 이벤트 | 변동 | 현금 |
| --- | --- | ---: | ---: |
| 0:00 | 시작 | | 10,000,000 |
| 0:30 | 서진해운 1,200주 @ 6,180 매수 | −7,416,000 | 2,584,000 |
| 1:00 | 월급 +300,000 / 인플레 −86,520 | +213,480 | 2,797,480 |
| 2:00 | 월급 +300,000 / 인플레 −92,924 | +207,076 | 3,004,556 |
| 2:30 | 다른 종목 손실 확정 | −178,000 | 2,826,556 |
| 3:00 | 월급 +300,000 / 인플레 −93,796 | +206,204 | 3,032,760 |

```
평가금액   1,200주 × 6,720 = 8,064,000
총자산     3,032,760 + 8,064,000 = 11,096,760
누적 투입  10,000,000 + 900,000 = 10,900,000
성과       +196,760  (+1.81%)
주문가능   floor(3,032,760 / 6,720) = 451주
```

## 3. 화면 1 — 방 만들기

**목적**: 방장이 한 판의 규칙을 정하고 초대코드를 만든다. 게임 시작 전 유일한 설정 지점.

| 블록 | 컨트롤 | 비고 |
| --- | --- | --- |
| 방 이름 | 텍스트 입력 (20자) | |
| 한 판 시간 | 세그먼트 `5분 / 7분 / 10분` | 차트 봉 단위와 정산 횟수를 결정 |
| 시작 자금 | 세그먼트 `100만 / 1,000만 / 1억` | 전원 동일 |
| 분당 정산 | 스테퍼 2개 — 월급(원/분), 인플레(%/분) | 상쇄 관계를 보조 문구로 설명 |
| 거래 종목 | 칩 다중 선택 | **목록 미확정** |
| 시장 변동성 | 세그먼트 `잔잔 / 보통 / 폭풍` | 봇의 공격성 + 돌발 뉴스 횟수 프리셋 |
| 규칙 | 토글 1개 — 돌발 뉴스 | |
| 봇 트레이더 | 스테퍼 (0~20) | 호가를 채우고 사람 주문의 반대편에서 거래 |
| CTA | `방 만들고 초대코드 받기` | 6자리 코드 발급 → 대기실 |

**설계 판단**

- 설정을 한 화면에 다 넣었다. 5분짜리 게임을 만드는 데 위저드 3단계를 태우면 배보다 배꼽이 크다.
- **사람 수는 설정하지 않는다.** 방장이 정하는 것은 봇 수뿐이고, 사람은 초대코드로 들어온 만큼 참가한다.
  봇 수는 유동성 손잡이다 — 0이면 사람끼리만 거래하므로 호가창이 비고 체결이 거의 안 난다.
  변동성 프리셋이 봇의 **행동**을, 봇 수가 **머릿수**를 정한다.
- 월급/인플레는 스테퍼로 열어뒀지만, 둘의 상쇄 관계를 깨면 게임 성격이 달라진다.
  잠그고 프리셋으로만 주는 것도 방법이다.
- 방을 만든다고 장이 열리지는 않는다. 방장이 대기실에서 시작을 눌러야 한다.

## 4. 화면 2 — 전체 시황

**목적**: 한 판의 상황판. "지금 뭐가 뛰고 있나"와 "내가 몇 등인가"를 한 화면에서 본다.

### 구성

1. **게임 헤더** (sticky) — 방 이름, `LIVE`, 남은 시간(mono 34px), 진행 바, `6명 + 봇 8`
2. **내 자산 카드**
   - 총자산 / 성과액 / 수익률 + `누적 투입 대비` 라벨 / 순위 배지
   - 현금 · 평가금액 · 실현손익 3분할
   - **분당 정산 스트립** — `다음 0:58` 카운트다운, 월급 누적(+900,000)과 인플레 누적(−273,240)을 좌우 타일로
   - 총자산 = 현금 + 평가금액 이 화면에서 검산돼야 하고, 월급·인플레 누적이
     왜 현금이 그 값인지를 설명해야 한다. 그래서 둘 다 노출한다.
3. **전체 종목 리스트** — 순번 · 종목명 · 섹터 · 스파크라인 · 현재가 · 등락률 / 정렬 `등락률순`·`거래대금순`
4. **자산 순위** — 순위 배지 · 닉네임 · 총자산 · 수익률(누적 투입 대비). 내 행은 틴트 + 액센트 바 + `나` 태그
5. **하단 탭바**

### 설계 판단

- 시황과 순위를 탭으로 나누지 않고 세로로 쌓았다. 5분 게임에서 탭 전환은 정보를 감추는 비용이 크다.
- 순위 리스트에 남의 보유 종목은 넣지 않았다 (미결정 참조).
- 스파크라인은 판 시작(기준가) 이후 전체 경로. 축·눈금 없이 방향만 읽는 용도.

## 5. 화면 3 — 개별 종목

**목적**: 한 종목을 보고 주문을 낸다. 내부 거래소이므로 **호가창이 곧 다른 참가자와 봇의 의사표시**다.

1. **헤더**: 뒤로 · 종목명 · 섹터 칩 · 남은 시간
2. **가격 블록**: 현재가(32px) · 기준가 대비 · 등락률 / 우측 고가·저가·거래량
   - "전일"이 없는 게임이므로 기준은 **판 시작가**. 표기는 `기준가` 로 통일.
3. **차트**: 캔들 + 거래량 바 + 현재가 수평선
   - 시간 단위 칩 `1초 / 5초 / 30초 / 전체` (기본 5초). 마지막 봉은 진행 중이다.
   - 기준가 수평선과 라벨을 항상 표시
4. **호가창** — 매도 5호가 / 스프레드 / 매수 5호가, 3열 `매도잔량 | 호가 | 매수잔량`
   - 잔량 막대는 표시된 10호가 중 최대 잔량 기준 상대 폭
   - **내 지정가 주문은 해당 호가 행에 `내 200` 배지로 표시** — 내부 거래소에서만 가능한 정보이고,
     "내 주문이 아직 안 붙었다"를 확인하는 유일한 수단
   - 하단에 총매도잔량 / 총매수잔량
5. **내 포지션**: 보유 수량 · 평단 · 평가손익
6. **주문 패널** (하단 고정): `지정가/시장가` · 가격/수량 스테퍼 · 비율 칩 · 주문금액 · 주문가능 · `매도`/`매수`

**설계 판단**

- 호가창 행 높이 44px. 국내 실제 앱은 28~32px로 더 조밀하지만, 모든 호가가 탭 대상이므로
  최소 터치 영역을 지켰다. 10호가로 늘리면 20행 = 880px이라 **5호가 고정 + 접힘 확장**을 권장.
- 주문 패널을 바텀시트가 아닌 인라인 고정으로 뒀다. 5분 안에 수십 번 주문하는 게임에서
  시트 열고 닫기는 명백한 마찰.
- 매수 = 빨강, 매도 = 파랑. 등락 색상과 같은 규칙.

## 6. 화면 4 — 돌발 뉴스 팝업

**딤 + 중앙 모달.** 화면을 막는다.

| 요소 | 내용 |
| --- | --- |
| 배지 | `돌발 뉴스` (상승색 틴트) + 남은 시간 |
| 헤드라인 | 20px / 700. 한 문장 |
| 영향 종목 카드 | 종목명 · 섹터 · **현재가 · 등락률** |
| 버튼 | `닫기` / `<종목명> 보러가기` (액센트) |
| 자동 닫힘 | 3초 진행 바 |

**설계 판단**

- 판을 통틀어 2~3회뿐이고 즉시 반응해야 하는 정보다. 이건 화면을 막을 자격이 있다.
  반대로 매분 반복되는 월급은 막으면 안 된다 (화면 5).
- **방향(↑↓)이나 예상 등락률은 알려주지 않는다.** 헤드라인을 읽고 판단하는 게 게임이다.
  대신 영향 종목의 현재가·등락률을 같이 보여줘서 "아직 안 움직였다"를 스스로 읽게 한다.
  시안의 예: 블루칩소프트 악재인데 현재가는 +0.66% — 아직 반영 전이다.
- 어느 화면 위에서든 뜬다. 개별 종목 화면에서 다른 종목 뉴스가 뜨면 `보러가기`가 이동 수단이 된다.

## 7. 화면 5 — 월급 입금 팝업

**딤 없는 토스트.** 하단(주문 패널 바로 위)에 뜬다. 거래를 막지 않는다.

| 요소 | 내용 |
| --- | --- |
| 헤더 | 지갑 아이콘 · `월급 입금 · 3분차` · 다음 지급까지 `0:58` · **+300,000** (액센트) |
| 인플레 | `인플레 차감 · 현금의 3%` · **−93,796** (하락색) |
| 결과 | `정산 후 현금` · **3,032,760원** |
| 자동 닫힘 | 2초 진행 바 |

**설계 판단**

- **월급과 인플레를 한 팝업에 합쳤다.** 같은 시점에 일어나는 한 번의 정산이고,
  매분 팝업이 두 개씩 뜨면 7분 판에서 12번 방해받는다.
- **상단이 아니라 하단이다.** 상단에 두면 현재가와 고가/저가를 가린다.
  그 화면에서 가장 중요한 숫자를 정보성 토스트가 가려서는 안 된다.
  하단에 두면 겹치는 것은 `내 보유` 카드뿐이고, 그 정보는 토스트가 대신 말해준다.
- 월급(+)은 액센트 라임, 인플레(−)는 하락색. 시세 색과 게임 색을 섞지 않는 규칙을 지켰다.

## 8. 갱신 주기 — "10초 단위가 적당한가?"

**결론: 10초는 이 게임에 너무 느리다.**

7분(420초) 한 판 기준으로 10초 갱신은 판 전체에서 **가격이 42번밖에 안 움직인다**.
플레이어 입장에선 사실상 정지 화면이고, 종료 직전 순위 역전을 놓친다.
내부 시뮬레이션 거래소에서는 내 주문이 체결됐는지를 10초 뒤에 아는 셈이 된다.

| 데이터 | 주기 | 방식 | 근거 |
| --- | --- | --- | --- |
| 호가창 · 체결 | 이벤트 발생 시 즉시, 클라이언트에서 **250ms 스로틀** | WebSocket push | 체결 이벤트가 곧 진실. 250ms보다 빠르면 사람이 못 읽는다 |
| 차트 | 서버가 **1초 틱** OHLC 생성, 기본 **5초봉** 집계 | 봉 확정 시 push + 진행 봉은 현재가로 갱신 | 7분 = 5초봉 84개 |
| 전체 종목 등락 | **1초** 스냅샷 브로드캐스트 | 8종목 × (현재가, 등락률, 스파크 1포인트) ≈ 200B/초 | 리스트가 살아 움직여야 "시황"이다 |
| 참가자 자산 순위 | **2초** 서버 집계 후 브로드캐스트 | N명 × 보유 평가 계산 | 순위는 1초마다 안 바뀐다 |
| 분당 정산 (월급·인플레) | **60초** 서버 이벤트 → 팝업 + 자산 화면 갱신 | | 규칙 자체가 분 단위 |
| 돌발 뉴스 | 이벤트 발생 시 즉시 push | | 늦으면 정보가 아니다 |
| 남은 시간 | 클라이언트 로컬 카운트다운, **5초마다** 서버 시각 동기화 | | |

시간 단위 칩(`1초 / 5초 / 30초`)이 의미 있으려면 서버가 **1초 틱을 원본으로 저장**해야 한다.
5초봉을 원본으로 저장하면 1초봉으로 되돌릴 수 없다.

**10초가 맞는 유일한 경우**: 한 판을 며칠 단위 리그로 바꿀 때.

레포에 기존 디자인 시스템이 없어 새로 정의했다.

| 항목 | 값 |
| --- | --- |
| 배경 | `#0A0C10` / 서피스 `#12151B` `#191D25` `#20252E` |
| 경계선 | `#242A34` `#2E3540` |
| 텍스트 | `#EDEFF3` / 보조 `#8B93A1` / 약함 `#5C6472` |
| 상승 · 매수 | `#FF4D5E` |
| 하락 · 매도 · 인플레 | `#4C8DFF` |
| 액센트 (CTA·타이머·내 항목·월급) | `#C6F24E` |
| 본문 폰트 | IBM Plex Sans KR |
| 숫자 폰트 | IBM Plex Mono (`tabular-nums`) |
| 최소 터치 영역 | 44px |

- 다크 기본. 숫자가 주인공인 화면이고, 빨강/파랑 대비가 어두운 바탕에서 가장 정확하게 읽힌다.
- 액센트 라임은 **게임성(타이머, 내 순위, 주 CTA, 월급)에만** 쓴다. 시세 색과 절대 섞지 않는다.
- 모든 수치는 mono + tabular-nums. 1초마다 갱신되는 숫자가 자리를 흔들면 안 된다.

## 10. 미결정 사항

**즉시 필요**
- **거래 종목 10개 목록** — 현재 시안의 종목명은 전부 자리표시용 가상 종목이다

**거래소 규칙**
- 체결 우선순위: 가격 우선 → 시간 우선으로 갈 것인가
- 봇 유동성 모델: 어떤 알고리즘이 호가를 대는가, 참가자 물량을 다 받아주는가
- 시장가 주문의 슬리피지 상한
- 상·하한가(±30%) 적용 여부
- 종목별 총 유동 주식 수 (한 명이 전량 사버리는 것을 막을 상한)
- 수수료/세금 반영 여부

**월급 · 인플레**
- 인플레가 평가금액에도 붙는가 (현재 설계는 현금만)
- 봇도 월급을 받고 인플레를 맞는가
- 현금이 마이너스가 될 수 있는가 (인플레 차감으로 미수 발생 처리)
- 시작 자금을 바꾸면 월급이 자동으로 따라 바뀌는가 (상쇄 관계 유지)
- 방장이 월급/인플레를 개별 조정할 수 있게 열어둘 것인가, 프리셋으로 잠글 것인가

**봇**
- 봇이 자산 순위에 사람과 함께 표시되는가 (현재 시안의 순위 리스트는 사람만)
- 봇이 순위 경쟁자인가, 순수 유동성 공급자인가
- 사람이 0명이거나 1명일 때도 판이 성립하는가 (연습 모드)

**돌발 뉴스**
- 뉴스 모달이 떠 있는 동안에도 시세는 계속 움직이는가 (거의 확실히 예 — 그래서 3초 자동 닫힘)
- 놓친 뉴스를 다시 볼 곳이 있는가 (방 정보 탭의 뉴스 로그?)
- 뉴스가 전원에게 동시에 뜨는가, 시차가 있는가
- 가짜 뉴스(노이즈)를 섞을 것인가

**게임 규칙**
- 남의 보유 종목 공개 여부
- 도중 이탈/재접속 처리
- 동점 처리

**화면**
- 대기실 화면
- 정산 결과 화면 (한 판이 끝나는 게임인데 결과 화면이 없다)
- 내 자산 탭 (보유 종목 목록 + 체결 내역 + 분당 정산 내역)
