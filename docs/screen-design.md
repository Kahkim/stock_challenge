# 모의주식 챌린지 — 모바일 화면 설계

**이 문서는 서버 구현을 따른다.** 화면이 서버를 정의하지 않는다.

기준: `claude/dreamy-knuth-bgjjrp` 브랜치 (`d7c4765`)
- `docs/API.md` — 엔드포인트 · SSE · 데이터 모델
- `src/config.js` — 종목 풀과 규칙 기본값
- `src/game.js` — 인플레·월급·무상증자의 실제 구현

비주얼 시안: `design/artboards/*.dc.html` (`node design/gen.mjs` 로 재생성)

## 0. 게임 규칙 (서버 확정)

| 항목 | 값 | 출처 |
| --- | --- | --- |
| 종목 | **10개 대학** — 서울대 1,200 / 연세대 2,500 / 고려대 3,400 / 한양대 1,800 / 동국대 900 / 건국대 2,200 / 홍익대 5,000 / 경희대 1,500 / 경기대 3,000 / 숭실대 4,200 | `STOCK_POOL` |
| 시작 자산 | 현금 1,000,000원, **주식 0주** | `seedMoney`, `initialShares: 0` |

| 무상증자 | 월급과 동시에, **보유자에게만** 최대 5% 비례 배정 | `bonusShares`, `_issueBonusShares` |

| 발행 주식 수 | 전체 시드머니 × 60% 를 종목 수로 나눠 시가총액 균등 | `floatCapitalRatio` |
| 서버 틱 | 250ms / SSE 푸시 400ms | `tickMs`, `PUSH_MS` |

### 인플레에 대한 정정

이전 버전의 이 문서와 시안은 "매분 현금이 3%씩 줄어든다"로 그려져 있었다. **틀렸다.**
서버는 현금을 건드리지 않고 적정가를 올린다 (`game.js:156-160`).
`cash -=` 는 청약 증거금과 주문 예치금에만 나온다.

이 차이는 화면에 그대로 드러난다.

- 아무것도 안 한 사람의 수익률은 **정확히 0%** 다. 잃지는 않는다. 다만 전원에게 뒤처진다.
- 화면에 "인플레로 −N원 차감" 같은 항목이 있으면 안 된다. 그런 숫자는 서버에 없다.
- 대신 **적정가(`fair`)와 괴리율(`vsFairPct`)** 을 노출해야 인플레가 보인다.

### 여기서 갈라지는 결정

- **돌발 뉴스는 서버에 없다.** `game.js` 에 news 가 한 군데도 없고 `notices[].kind` 는
  `info · salary · bonus · ipo · open · close` 뿐이다. 시안에는 남겨두기로 했으므로
  **서버에 요청이 필요하다** (9절).
- 정규장 길이는 서버 기본값 15분을 따랐다. 이전 대화의 "5~10분"과 다르다.
  `durationMin` 은 1~180 이라 바꿀 수는 있지만, 봇 배합과 무상증자 상한은 더 긴 판을 전제로
  튜닝된 값이므로 (`config.js` 주석의 실측 기록) 바꾸려면 재튜닝이 필요하다.

## 2. 화면별 설계

### 1 · 방 만들기

종목 목록은 `GET /api/meta` 의 `stockPool` 을 그대로 그린다 — **화면에 하드코딩하지 않는다.**
10개 대학을 색 점과 초기가와 함께 칩으로 보여주고, 2개 이상 선택하게 한다
(1개 이하면 `400 TOO_FEW_STOCKS`).

블록: 방 이름 / 거래 종목 / 진행(정규장 길이 · 개장 공모) / 자산(시작 현금 · 월급) /
참가(봇 수) / 고급 설정(접힘) / CTA.

- **사람 수는 정하지 않는다.** 방장이 정하는 건 봇 수뿐이고 사람은 참가코드로 들어온다.
- 서버는 범위를 벗어난 값을 거절하지 않고 **잘라서** 돌려준다. 응답의 `config` 가 실제
  적용값이므로 그걸 다시 화면에 표시해야 한다.
- 고급 설정(인플레·증자율·변동성·봇 성향 배합)은 접어뒀다. 항목이 20개가 넘어 다 펼치면
  방을 못 만든다.

### 2 · 대기실

참가코드 6자를 화면에서 가장 큰 요소로 둔다. 복사/공유 버튼.
참가자 목록 + `사람 6 · 봇 30`, 종목 칩, 규칙 요약 칩, 방장만 보이는 `게임 시작`.

시작하면 난입이 막히므로(`409 ALREADY_STARTED`) 그 경고를 CTA 밑에 둔다.

### 3 · 개장 공모 — 이 게임에서 가장 중요한 화면

**전원 주식 0주로 시작한다.** 45초 안에 청약하지 않으면 끝까지 0주이고,
무상증자를 한 주도 못 받아 수익률이 0%에 고정된다.

그래서 이 화면은 경고 배너로 시작한다. 부드럽게 쓰면 안 된다 —
청약을 놓친 사람은 15분 동안 아무것도 할 수 없다.

- 45초 카운트다운을 헤더에 크게 (경고색)
- 종목별 청약 현황: 초기가 · 발행 예정 수량 · **현재 청약 수요** · 청약률(수요/발행)
- 하단 청약 패널: 가격(호가 단위) · 수량(10주 단위) · 예치 증거금 · 남는 현금
- 청약 즉시 `price × qty` 가 현금에서 빠지고, 마감 시 낙찰 차액과 미배정분이 자동 환불

### 4 · 전체 시황

**인플레가 적정가를 분당 5% 올리므로 전 종목이 상승한다.**
8분 시점의 시안에서 10종목이 전부 +20~54% 다. 이 상태에서 등락률 색(빨강)은 정보가 아니다.

그래서 이 화면은 세 가지를 같이 보여준다.

| 지표 | 의미 |
| --- | --- |
| 현재가 + 시초가 대비 등락률 | 절대 성과 — 종목 간 상대 비교용 |
| **적정가 (`fair`)** | 인플레와 개별 실적이 반영된 이론가 |
| **괴리율 (`vsFairPct`)** | 양수면 거품, 음수면 저평가. **실제 매매 신호** |

괴리율이 +5% 이상이면 앰버 `거품` 배지를 붙인다. 그 외에는 무채색 숫자다.
정렬은 `등락률순` / `괴리율순` 두 가지.

내 자산 카드는 `me` 를 그대로 편다: 총자산 `nav`, 성과 `nav − invested`,
현금 `cash`, **묶인 현금 `lockedCash`**, 평가금액, 실현손익 `realized`,
그리고 분당 정산 스트립(월급 누적 · 무상증자 누적 주식 수 · 다음 정산까지).

수익률은 **`nav / invested − 1`** 이다. `invested` 는 시드머니 + 누적 월급이라
월급이 들어오면 기준선도 같이 커진다. 시드머니 기준으로 계산하면 전원이 함께 부풀어
실력을 나타내지 못한다.

순위는 `snapshot.ranking` (기본적으로 사람만). 최하위가 정확히 0.00% 인 것이 이 게임의 성질이다.

### 5 · 개별 종목 · 호가 탭

`호가 / 차트 / 체결` 탭으로 나눴다. 390px 폭에서 10단계 호가와 차트와 주문 패널을
한 화면에 넣을 수 없다. 헤더(현재가·괴리율)와 주문 패널은 탭과 무관하게 항상 보인다.

- **호가 10단계.** 3열 `매도잔량 | 호가 | 매수잔량`, 행 높이 44px (모든 호가가 탭 대상).
- **빈 칸을 정상으로 그린다.** 서버 `depth` 는 값이 있는 호가만 보내므로 사다리에 구멍이
  생긴다. API 문서에 따르면 매도 호가는 전체 시간의 약 20% 동안 비어 있다.
- 내 미체결 주문은 해당 호가 행에 `내 60` 배지로 표시한다.
- 미체결 주문 카드: `100주 중 40주 체결 · 60주 미체결 · 묶인 현금 168,000` + 취소 버튼.
  서버가 주문 응답으로 `filled` / `resting` 를 주므로 부분 체결을 그대로 보여줄 수 있다.
- 주문 패널: 지정가/시장가 · 가격(호가 단위 증감) · 수량(10주 단위) · 비율 칩 ·
  주문금액 · **수수료** · 주문가능 · 매도/매수.
- **시장가 실패를 UI에 넣었다.** `NO_COUNTERPARTY` 는 예외가 아니라 정상 상황이므로
  시장가 옆에 지정가 입력을 항상 둔다.

### 6 · 개별 종목 · 차트 탭

`GET /chart` 의 `history[]` 를 **체결가(실선)와 적정가(점선) 두 선**으로 그린다.
두 선의 간격이 곧 거품의 크기다. 이 그림 하나가 괴리율 숫자보다 직관적이다.

아래에 `snapshot.tape` 기반 최근 체결. `side` 는 체결을 일으킨 쪽이므로 매수면 상승 체결이다.

### 7 · 월급·무상증자·체결 팝업

**딤 없는 토스트.** 하단(주문 패널 위)에서 위로 쌓인다. 위가 오래된 것, 아래가 최신.

- **월급과 무상증자는 한 팝업이다.** 같은 시점의 한 정산이고, 매분 팝업이 두 개씩 뜨면
  15분 판에서 30번 방해한다.
- 무상증자는 종목별 배정 수량을 보여준다 (`서울대 +8 · 한양대 +4`).
  주식이 없으면 이 줄이 비는데, 그게 이 게임의 경고다.
- 인플레 줄은 **"현금을 깎지 않습니다 — 적정가가 5% 올랐습니다"** 로 적는다.
- 체결 팝업은 `me.newFills` 를 그대로 띄운다. 직전 전송 이후 신규분만 오므로 중복이 없다.
- **상단이 아니라 하단이다.** 상단에 두면 현재가와 고가/저가를 가린다.

### 8 · 돌발 뉴스 팝업 — 서버 미구현

**딤 + 중앙 모달.** 유일하게 화면을 막는 팝업이다. 판당 2~3회뿐이고 즉시 반응해야 한다.

- 헤드라인 한 줄 + 영향 종목 카드(현재가 · **괴리율**) + `닫기` / `보러가기` + 3초 자동 닫힘
- **방향(↑↓)이나 예상 등락률은 알려주지 않는다.** 헤드라인을 읽고 판단하는 게 게임이다.
  대신 괴리율을 같이 보여준다 — 시안의 예는 저평가(−10.9%) 종목에 호재가 뜬 상황이다.

### 9 · 결과

`GET /result` 의 `humanRanking` 으로 시상한다 (`ranking` 은 봇 포함).
우승자 카드 + 사람 순위(성과액과 수익률) + 종목별 결과(시초/고/저/종가/거래량/발행) + 수수료 합계.

## 3. 화면 요소 → 서버 필드

| 화면 요소 | 필드 |

| 적정가 · 괴리율 배지 | `stocks[].fair`, `stocks[].vsFairPct` |

| 총자산 · 수익률 | `me.nav`, `me.nav / me.invested - 1` |
| 현금 · 묶인 현금 | `me.cash`, `me.lockedCash` |
| 보유 · 평가손익 | `me.holdings[]` |
| 미체결 주문 | `me.openOrders[]` |
| 체결 팝업 | `me.newFills[]` |
| 월급·증자 팝업 | `snapshot.notices[]` (`kind: salary` / `bonus`) |
| 순위표 | `snapshot.ranking[]` / `result.humanRanking` |
| 공모 수요 | `stocks[].ipoDemand` |
| 종목 색 | `stocks[].color` |

### 갱신 주기

서버가 이미 정해뒀다. 화면이 따로 폴링 주기를 설계할 필요가 없다.

| | |
| --- | --- |
| SSE `state` | **400ms** — `snapshot` + `me` 가 한 번에 온다 |
| 서버 틱 | 250ms |
| 차트 | 1초 1점, 최대 1800점 |
| 폴백 | `GET /state` 폴링 (SSE 불가 환경) |
| 관전 | 토큰 없이 SSE 연결 → 공개 정보만. 프로젝터 현황판용 |

`EventSource` 는 헤더를 못 붙이므로 토큰은 쿼리스트링으로 보낸다.

## 4. 시안의 수치 — 검산 가능한 원장

시안은 **정규장 경과 8분 2초** 한 순간이다. 화면의 모든 금액은 `design/gen.mjs` 의
원장 계산에서 나오고, 무결성 검사(호가 단위·lotSize·손익 일치)를 통과하지 못하면
생성 자체가 실패한다.

평균단가가 1,242원에서 861원으로 내려갔다. **보유 자체가 보상받는 구조**다.

- 색은 각각 한 가지 일만 한다. 라임을 시세에 쓰지 않고, 빨강/파랑을 게임 UI에 쓰지 않는다.
- **대학 색은 그대로 못 쓴다.** 서버가 주는 `color` 는 어두운 교색(서울대 `#1b3f7a`,
  홍익대 `#1a1a2e`)이라 다크 배경에서 안 보인다. 색상(hue)은 유지한 채 흰색과 45% 섞어
  밝힌다 (`gen.mjs` 의 `lighten()`).
  다만 10개 중 파란 계열이 4개라 **색만으로 종목을 구분할 수는 없다** — 이름을 항상 같이 쓴다.

## 6. 서버에 요청할 것

**돌발 뉴스.** 시안에 남기기로 했으므로 서버 지원이 필요하다.

- `notices[].kind` 에 `news` 추가
- 뉴스 객체에 영향 종목 코드와 헤드라인 텍스트
- 해당 종목의 `fair` 에 일회성 충격을 주는 이벤트 (지금 인플레 드리프트는 전 종목 공통이다)
- 방 설정에 뉴스 빈도 (현재 `config.js` 에 없음)

없어도 나머지 8개 화면은 지금 API 그대로 만들 수 있다.

## 7. 미결정

**공모**
- 청약을 아무도 안 하면 시초가가 어떻게 정해지는가
- 공모 중 참가한 사람은 어떻게 되는가 (지금은 `lobby` 에서만 참가 가능)

**화면**
- `내 자산` 탭 (보유 목록 + 체결 내역 + 정산 내역) — 하단 탭에 자리만 있고 설계 없음
- `방 정보` 탭 (규칙 요약 + 놓친 공지 로그)
- 관전 모드 전용 레이아웃 (프로젝터용 대화면. 지금 시안은 전부 390px 모바일)
- 재접속 · 이탈 처리

**규칙**
- 정규장 길이를 15분에서 줄일 것인가 (줄이면 봇 배합·증자율 재튜닝 필요)
- 봇을 순위표에 `isBot` 로 구분해 노출할 것인가 (지금은 완전히 숨김)
- 현금이 마이너스가 될 수 있는가
