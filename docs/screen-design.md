### 인플레율이 실제로 정하는 것

서버측 실측에 따르면 **인플레율은 밸런스를 바꾸지 못한다.** 0%에서 10%까지 바꿔도
무행동자 등수·체결가 변동·체결량·호가 균형이 모두 같았다. 적정가 상승이 체결가로
전달되는 통로가 `value` 봇 하나뿐인데 기본 비중이 2%라 시장을 못 움직이기 때문이다.

이 값이 정하는 건 **괴리율이 쓸모 있는 숫자가 되느냐**다.

| 인플레 | 괴리율 평균 | 화면에서 |
| --- | --- | --- |
| 5%/분 | −44.8% | 전 종목 영구 저평가. 거품 배지가 한 번도 안 뜬다 |
| **0.5%/분 (현재)** | **+3.9%** | 거품/저평가가 종목마다 갈린다 |

그래서 **등락률과 괴리율은 서로 다른 질문**이고 화면은 둘 다 보여준다.
등락률은 시초가 대비 성과, 괴리율은 적정가 대비 고평가/저평가다.
시안 시점에서 10종목 중 5개가 오르고 5개가 내린다 — 등락률 색은 정보다.

## 2. 화면별 설계

### 1 · 방 만들기
`GET /api/meta` 의 `stockPool` 을 그대로 그린다 — 하드코딩하지 않는다. 2개 이상 선택
(1개 이하면 `400 TOO_FEW_STOCKS`). 서버는 범위를 벗어난 값을 거절하지 않고 **잘라서**
돌려주므로, 응답의 `config` 를 화면에 다시 표시한다. 사람 수는 정하지 않는다 — 봇 수만 정하고
사람은 참가코드로 들어온다.

### 2 · 대기실
참가코드 6자가 가장 큰 요소. 참가자 목록은 SSE `snapshot.players` 로 실시간으로 들어온다
(폴링 불필요, `phase === "lobby"` 일 때만 온다). 시작하면 난입 불가(`409 ALREADY_STARTED`).
사람이 예상과 다르게 왔을 때를 위해 **봇 수 조정**(`POST /config`)을 여기 둔다 —
`playerToken` 은 유지되지만 `playerId` 가 바뀌므로 응답 뒤 `GET /me` 로 갱신해야 한다.

### 3 · 개장 공모 — 승패가 갈리는 화면
전원 주식 0주로 시작한다. 45초 안에 청약하지 않으면 끝까지 0주이고, 무상증자를 한 주도
못 받아 수익률이 0%에 고정된다. 경고를 화면에서 가장 강한 요소로 둔다.

**낮게 쓰면 한 주도 못 받는다.** 실서버 상대 테스트에서 초기가 +5% 청약이 전량 탈락했다.
단일가 배정이라 높게 써도 낙찰가로 결제되고 차액은 전액 환불되므로, 화면은 기본값을
초기가 +20%로 두고 `+10/+20/+30%` 칩을 제공하며 이 성질을 명시한다.

청약 0건이면 시초가는 초기가 그대로이고 **한 주도 발행되지 않는다**(`issued: 0`,
`공모 미달` 공지). 그 종목은 정규장에서 매도 호가가 영원히 비므로 **미발행 배지**를 붙인다.

### 4 · 전체 시황
게임 헤더(남은 시간·진행 바) / 내 자산 카드 / 종목 리스트 / 사람 순위.

- 종목 행은 **현재가 · 등락률 · 적정가 · 괴리율**을 함께 보여준다. 괴리율 배지에는 항상
  `괴리` 접두어를 붙여 등락률과 구별하고, +5% 이상이면 앰버 `거품` 으로 바꾼다.
- 정렬은 `등락률순` / `괴리율순`.
- 내 자산 카드는 `me` 를 그대로 편다 — `nav`, `nav − invested`, `cash`, `lockedCash`,
  평가금액, `realized`, 월급 누적, 무상증자 누적.
- 순위는 `snapshot.ranking`(상위 20명). **내 순위는 `me.rank` / `me.rankTotal`** 로 따로 온다.
- 수익률은 `nav / invested − 1`. `invested` 는 시드머니 + 누적 월급이라 월급이 들어오면
  기준선도 같이 커진다.

### 5 · 개별 종목 · 호가 탭
`호가 / 차트 / 체결` 탭. 390px 폭에 10단계 호가와 차트와 주문 패널을 한 번에 못 넣는다.
헤더(현재가·괴리율)와 주문 패널은 탭과 무관하게 항상 보인다.

- 호가 10단계, 행 높이 44px. 좌우 잔량 셀은 **같은 폭**이어야 막대 길이를 비교할 수 있다.
- 서버 `depth` 는 값이 있는 호가만 보내므로 사다리에 구멍이 생긴다. 매도 호가는 전체 시간의
  약 19% 동안 빈다 — 정상 상태로 그린다.
- 내 미체결 주문은 해당 호가 행에 `내 60` 배지로 표시한다.
- **미체결 주문 카드와 취소 버튼은 주문 패널 안에 둔다.** 토스트가 절대 덮으면 안 되기 때문이다.
- 수량 상한은 **`me.tradable[].maxBuyQty` / `maxSellQty`** 를 쓴다. 직접 계산하지 않는다 —
  부하 테스트에서 거부된 주문의 83%가 `INSUFFICIENT_CASH` 였다. `maxBuyQty` 는 현재가
  기준이므로 지정가를 더 높게 넣으면 그만큼 줄인다.
- 시장가는 반대 호가가 없으면 `NO_COUNTERPARTY` 로 실패한다. 정상 상황이므로 지정가 입력을
  항상 옆에 둔다.

### 6 · 개별 종목 · 차트 탭
`GET /chart` 의 `history[]` 를 **체결가(실선)와 적정가(점선)** 두 선으로 그린다.
두 선의 간격이 곧 거품의 크기다. 아래에 `snapshot.tape`(최근 20건) 기반 체결 내역.

### 7 · 월급·증자·체결 토스트
딤 없는 토스트. **주문 패널 위에만** 쌓는다.

- 월급과 무상증자는 같은 시점의 한 정산이므로 팝업 하나로 합친다.
- 인플레 줄은 "현금을 깎지 않습니다 — 적정가가 분당 N% 올랐습니다". **숫자는
  `snapshot.config.inflationPerMin` 에서 읽는다.**
- 체결 토스트는 `me.newFills` 를 그대로 띄운다 — 직전 전송 이후 신규분만 오므로 중복이 없다.

### 8 · 돌발 뉴스 — 배너 + 토스트, 모달 금지
판당 약 12건이다. **화면을 막으면 게임이 안 된다.** 활성 뉴스는 시황 상단 배너로 계속 보여주고,
새로 뜬 순간에만 하단 토스트로 알린다.

- **토스트에는 즉시 체결되는 주문 버튼이 필요하다. 편의가 아니라 밸런스다.**
  서버 실측(24명 중 등수): 지정가를 현재가에 걸면 **15.1등**(즉시 체결률 23%),
  두 호가 위로 지르면 **5.3등**(67%). 소극적으로 주문하면 현금이 호가에 묶인 채
  인플레를 맞아 가만히 있느니만 못하다.
- 그래서 `바로 매수`(현재가 +2%)와 `바로 매도`(−2%)를 둔다. **둘 다 둔다** — 매수만 두면
  악재 뉴스에 매수를 권하는 셈이라 "헤드라인으로 판단한다"는 설계가 무너진다.
- `sign` 과 `impactPct` 는 서버가 주지만 **화면에 쓰지 않는다.** 방향이 그대로 드러난다.
- 새 뉴스는 `id` 가 처음 보이는 것으로 판별한다. `snapshot.news[]` 는 지금 효력이 살아 있는
  것만 담는다.

### 9 · 결과
`humanRanking` 으로 시상한다(`ranking` 은 봇 포함). 우승자 · 사람 순위 · 종목별 결과
(시초/고/저/종가/거래량/발행) · 수수료 합계. `newsLog` 로 지나간 뉴스를 차트 위에 얹을 수 있다.

## 3. 화면 요소 → 서버 필드

| 화면 요소 | 필드 |
| --- | --- |
| 남은 시간 | `snapshot.remainSec` (공모 중 `ipoRemainSec`) |
| 현재가 · 등락률 | `stocks[].last`, `stocks[].changePct` |
| 적정가 · 괴리율 | `stocks[].fair`, `stocks[].vsFairPct` |
| 시가/고가/저가/거래량/발행 | `stocks[].open / high / low / volume / issued` |
| 호가 10단계 | `stocks[].depth.bids / asks` |
| 체결 틱 | `snapshot.tape` (최근 **20건**) |
| 차트 2선 | `GET /chart` → `history[].price`, `history[].fair` |
| 돌발 뉴스 | `snapshot.news[]` · `notices[].kind === "news-up" / "news-down"` |
| 총자산 · 수익률 | `me.nav`, `me.nav / me.invested - 1` |
| 내 순위 | `me.rank` / `me.rankTotal` |
| 수량 입력 상한 | `me.tradable[].maxBuyQty` / `maxSellQty` |
| 현금 · 묶인 현금 | `me.cash`, `me.lockedCash` |
| 보유 · 평가손익 | `me.holdings[]` |
| 미체결 주문 | `me.openOrders[]` |
| 체결 토스트 | `me.newFills[]` |
| 월급 공지 | `snapshot.notices[]` (`kind: salary`) |
| **무상증자 개인 배정량** | **서버 필드 없음** — 6절 참조 |
| 로비 참가자 | `snapshot.players` (`phase === "lobby"` 전용) |
| 순위표 | `snapshot.ranking[]` (상위 20) / `result.humanRanking` |
| 종목 색 | `stocks[].color` |

### 갱신 주기

서버가 정한다. 화면이 따로 폴링 주기를 설계할 필요가 없다.

| | |
| --- | --- |
| SSE `state` | **400ms** — `snapshot` + `me` 가 한 번에 온다 |
| 서버 틱 | 250ms |
| 차트 | 1초 1점, 최대 1800점 |
| 폴백 | `GET /state` 폴링 |
| 관전 | 토큰 없이 SSE 연결 → 공개 정보만 (프로젝터 현황판) |

`EventSource` 는 헤더를 못 붙이므로 토큰은 쿼리스트링으로 보낸다.

## 4. 시안의 수치 — 검산 가능한 원장

시안은 **정규장 경과 8분 2초** 한 순간이다. 모든 금액은 `design/gen.mjs` 의 원장 계산에서
나오고, 무결성 검사(호가 단위 · lotSize · 손익 일치 · **오더북 교차 여부**)를 통과하지
못하면 생성이 실패한다.

| 시각 | 이벤트 | 변동 | 현금 |
| --- | --- | ---: | ---: |
| 00:00 | 시작 | | 1,000,000 |
| 00:00 | 공모 배정 서울대 120주 @ 1,240 (수수료 없음) | −148,800 | 851,200 |
| 01:00 | 월급 / 증자 서울대 +6 | +100,000 | 951,200 |
| 01:20 | 동국대 100주 @ 950 매수 | −95,143 | 856,057 |
| 01:50 | 동국대 100주 @ 920 매도 (실현 −3,281) | +91,862 | 947,919 |
| 02:00 · 03:00 | 월급 2회 / 증자 서울대 +6, +6 | +200,000 | 1,147,919 |
| 03:30 | 한양대 80주 @ 1,900 매수 | −152,228 | 995,691 |
| 04:00~08:00 | 월급 5회 / 증자 서울대 +6·+7·+7·+7·+8, 한양대 +4×5 | +500,000 | 1,495,691 |
| 08:02 | 한양대 100주 @ 1,950 주문 → **40주 체결** | −78,117 | 1,417,574 |
| 08:02 | 60주 미체결 · 증거금 예치 `ceil(1,950×60×1.0015)` | −117,176 | 1,300,398 |

```

평단       서울대 860 (148,800/173) · 한양대 1,645 (230,345/140)
```

**부분 체결이 서버 규칙을 지키는지 확인할 것.** 지정가 매수는 최우선 매도가 지정가 이하일
때만 체결된다(`orderbook.js`). 시안은 1,950 매도호가를 40주 소진하며 체결되고 남은 60주가
1,950 최우선 매수로 남은 상태다 — 체결가 1,950 이 곧 `last` 이고 체결 테이프 마지막 줄과
같다. `gen.mjs` 가 교차 상태와 체결 불가 조합을 검사한다.

## 6. 서버에 남은 요청 — 무상증자 개인 배정량

돌발 뉴스는 **전부 구현됐다**(`notices[].kind` 에 `news-up`/`news-down`, `snapshot.news[]`,
적정가 일회성 충격, `config.news` 로 빈도·강도 조절). 더 요청할 것이 없다.

남은 것은 하나다. **무상증자의 개인·종목별 배정 수량을 서버가 주지 않는다.**
`_issueBonusShares` 는 `_pushFill` 을 부르지 않아 `me.newFills` 에 들어오지 않고,
`PlayerView` 에도 관련 필드가 없다. 클라이언트로 오는 유일한 신호는 시장 전체 합계 공지
한 줄이다.

지금은 화면이 역산한다 — **보유 증가분 − 이번 푸시의 체결분 = 증자분.** 접속이 끊기면
누계가 0부터 다시 센다. 서버가 다음 중 하나를 주면 정확해진다.

- `_issueBonusShares` 에서 `_pushFill(p, 'buy', s, 0, bonus, '증자')` 로 체결 내역에 남기거나
- `PlayerView` 에 `bonusTotal` 또는 `lastBonus[]` 추가

## 7. 미결정

**화면**
- `방 정보` 탭 (규칙 요약 + 놓친 공지·뉴스 로그)
- 관전 모드 전용 레이아웃 (프로젝터용 대화면. 지금 시안은 전부 390px 모바일)
- 재접속 처리 — 서버는 복구를 지원하지만 화면이 아직 쓰지 않는다
- 공모 미달 종목(`issued === 0`)을 개장 공모 화면에서 어떻게 보여줄 것인가
  (정규장에는 미발행 배지를 붙였다)

**규칙**
- 정규장 길이를 15분에서 줄일 것인가. 줄일 때 봇 배합·증자율 재튜닝이 필요한지는 **미검증**이다
  (실측으로 확인된 것은 증자 상한 5%와 `lookbackSec` 120초 두 가지뿐이다)
- 봇을 순위표에 `isBot` 로 구분해 노출할 것인가 (지금은 완전히 숨김)
