## 1. 요청하신 것 — 돌발뉴스, 전부 구현됐습니다

설계 문서 6절 "서버에 요청할 것"의 네 항목이 모두 들어갔습니다. 8번 화면을 만드셔도 됩니다.

| 요청 | 구현 |
| --- | --- |
| `notices[].kind` 에 `news` 추가 | `news-up` / `news-down` 두 종류로 들어갑니다 |
| 뉴스 객체에 영향 종목 코드와 헤드라인 | `snapshot.news[]` — 아래 참조 |
| 해당 종목 `fair` 에 일회성 충격 | 정확히 그렇게 동작합니다. 전 종목 공통 드리프트와 별개입니다 |
| 방 설정에 뉴스 빈도 | `config.news.*` — 빈도·강도·수명·호재비율 전부 조절 가능 |

```jsonc
"news": [{
  "id": "n1366_jq3m",
  "code": "HYU", "name": "한양대",
  "sign": -1,                              // 1 호재 / -1 악재
  "headline": "한양대 차익실현 매물 출회",
  "impactPct": -6.9,                       // 적정가에 준 충격
  "ageSec": 12, "lifeSec": 90              // 뜬 지 12초, 총 90초간 유효
}]
```

- **`snapshot.news[]` 는 지금 효력이 살아 있는 뉴스만** 담습니다. 모달을 띄울 새 뉴스는
  `id` 가 처음 보이는 것으로 판별하세요. 지나간 뉴스 전체는 `result.newsLog` 에 있습니다.
- 평균 70초 간격, 15분에 **약 12건**, 호재:악재 ≈ 5:5, 동시 최대 3건.
  설계 문서의 "판당 2~3회"보다 훨씬 잦습니다. **12번 화면을 막으면 게임이 안 됩니다.**
  딤 모달 대신 상단 배너나 짧은 토스트를 권합니다.
- 헤드라인은 **가상 종목의 수급에 대한 서술만** 씁니다. 실제 대학에 대한 사실 주장
  (비리 의혹 같은 것)은 만들지 않습니다. 화면을 캡처했을 때 진짜 기사처럼 읽히면 안 되니까요.
- `sign` 을 주므로 방향을 숨기려면 화면에서 쓰지 않으면 됩니다. 설계 의도(헤드라인으로 판단)에
  동의합니다. 다만 `impactPct` 는 방향이 그대로 드러나니 같이 숨기셔야 합니다.

### ⚠️ 뉴스 팝업에는 반드시 "즉시 체결되는 주문 버튼"이 필요합니다

이건 편의 기능이 아니라 **밸런스의 일부**입니다. 측정 결과입니다 (24명 중 등수).

| 뉴스 대응 방식 | 등수 | 즉시 체결률 | 최종 현금비중 |
| --- | --- | --- | --- |
| 지정가 `현재가` | 15.1등 | 23% | 55% |
| **지정가 `현재가 +2%`** | **5.3등** | **67%** | — |

소극적으로 주문하면 현금이 호가에 묶인 채 인플레이션을 맞아 **가만히 있느니만 못합니다.**
`보러가기` 말고 **`바로 매수`** 를 두고, 현재가보다 한두 호가 위로 지르게 하세요.

## 2. 인플레이션이 5%/분 → **0.5%/분** 으로 바뀌었습니다

설계 문서의 "전 종목이 +20~54% 상승한다"는 전제가 바뀝니다. **실측 +10% 수준입니다.**

왜 낮췄는지가 중요합니다. **인플레율은 게임 밸런스를 전혀 바꾸지 못합니다.**
0%에서 10%까지 바꿔가며 재봤는데 무행동자 등수, 체결가 변동, 체결량, 호가 균형이 전부 같았습니다.
적정가 상승이 실제 체결가로 전달되는 통로가 `value` 봇 하나뿐인데 기본 비중이 2%라
(봇 50명 중 1명) 시장을 움직이지 못합니다.

**이 값이 실제로 정하는 건 괴리율이 쓸모 있는 숫자가 되느냐입니다.**

| 인플레 | 괴리율 평균 | 종목 간 편차 | 화면에서 |
| --- | --- | --- | --- |
| 5%/분 (설계 기준) | **−44.8%** | ±23.8%p | 전 종목이 영구 저평가. **거품 배지가 절대 안 뜸** |
| **0.5%/분 (현재)** | **+3.9%** | ±34.7%p | 거품/저평가가 종목마다 갈림 |

**설계하신 "괴리율 +5% 이상이면 앰버 거품 배지"가 이제야 제대로 작동합니다.**
5%/분이었다면 그 배지는 15분 내내 한 번도 안 떴을 겁니다.

그리고 이 변화 때문에 **4번 화면의 전제가 뒤집힙니다.** 전 종목이 다 빨간 상태가 아니라,
오르는 종목과 내리는 종목이 갈립니다. 등락률 색이 다시 정보가 됩니다.

> 7번 팝업의 인플레 문구는 `"현금을 깎지 않습니다 — 적정가가 5% 올랐습니다"` 로 되어 있는데,
> 숫자를 하드코딩하지 말고 `snapshot.config.inflationPerMin` 에서 읽으세요. 기본 0.005입니다.

## 3. 새로 생긴 필드

### `me.tradable[]` — 수량 입력의 상한

설계 문서 4절의 `주문가능 floor(1,215,300 / (2,850 × 1.0015) / 10) × 10 = 420주` 계산을
**서버가 대신 해서 보냅니다.** 직접 계산하지 마세요.

```jsonc
"tradable": [{
  "code": "SNU", "name": "서울대", "last": 1105,
  "maxBuyQty": 2210,     // 현재가 기준, 수수료 포함해 살 수 있는 최대 (lotSize 배수)
  "maxSellQty": 1120     // 미체결 매도에 묶이지 않은 보유분 (lotSize 배수)
}]
```

부하 테스트에서 **거부된 주문의 83%가 `INSUFFICIENT_CASH`** 였습니다. 수수료와 호가 단위
때문에 화면 계산이 어긋나기 쉽습니다. 참여 종목 전체가 오므로 보유가 없는 종목도 들어 있습니다.

`maxBuyQty` 는 **최우선 매도호가 기준**입니다(없으면 현재가). 시장가로 그대로 보내면 되고, 엔진은 현금이 닿는 만큼만 삽니다.

### `me.rank` / `me.rankTotal` — 내 순위

`snapshot.ranking` 이 **상위 20명까지만** 오게 바뀌었습니다(아래 4절). 내 순위는 여기서 읽으세요.
순위표에 안 실려도 항상 옵니다.

### `snapshot.players` — 로비 참가자 명단

**`phase === "lobby"` 일 때만** 옵니다. 2번 대기실에서 참가자가 들어오는 걸 SSE로 실시간으로
받을 수 있습니다. `GET /api/rooms/{code}` 를 폴링할 필요가 없습니다.
시작 뒤에는 오지 않습니다(봇까지 실으면 커집니다).

```jsonc
"players": [ { "id": "p1_6ze7", "name": "앨리스" } ]
```

## 5. 새 엔드포인트 두 개 — 행사 운영용

### `POST /api/rooms/{code}/config` — 시작 전 설정 변경 *(방장)*

사람이 예상보다 적게(또는 많이) 왔을 때 봇 수나 진행 시간을 손볼 수 있습니다.
`phase === "lobby"` 일 때만. 요청 형식은 방 만들기와 같고 넘긴 항목만 덮어씁니다.

**이미 나눠준 `playerToken` 은 그대로 유지됩니다** — 다시 입장시킬 필요 없습니다.
다만 내부적으로 판을 다시 만들기 때문에 **`playerId` 는 바뀝니다.**
화면이 `playerId` 를 들고 있다면 응답 뒤 `GET /me` 로 갱신하세요.

2번 대기실에 "봇 수 조정" 컨트롤을 넣으면 유용합니다.

### `POST /api/rooms/{code}/end` — 조기 마감 *(방장)*

남은 시간과 무관하게 즉시 마감합니다. 미체결 주문은 전부 취소되고 예약분이 반환됩니다.
행사 진행이 밀릴 때 씁니다.

## 6. `seed` — 같은 판을 그대로 재현합니다

방 만들 때 `config.seed` 에 정수를 넣으면 **완전히 같은 게임이 재현**됩니다.
넣지 않으면 매번 다른 판이 되고, 그때 쓰인 시드가 응답의 `seed` 로 돌아옵니다.

`design/gen.mjs` 의 원장 검산에 쓰실 수 있습니다. 시드를 고정하고 서버를 돌리면
시안의 숫자를 **실제 서버 출력과 대조**할 수 있습니다.

## 7. 미결정이라고 적으신 것에 대한 답

**"청약을 아무도 안 하면 시초가가 어떻게 정해지는가"**

해당 종목은 `initialPrice` 를 시초가로 유지하고, 발행 물량은 **한 주도 배정되지 않습니다**
(`issued: 0`). 공지가 하나 나갑니다: `"{종목명} 공모 미달 — 시초가 N원"` (`kind: "ipo"`).

그 종목은 아무도 주식이 없으므로 정규장에서 **매도 호가가 영원히 비어 있습니다.**
매수 주문만 쌓이고 체결이 안 됩니다. 화면에서 `issued === 0` 인 종목은
"미발행" 배지를 붙여 구분해주시는 게 좋습니다.

수요가 발행량보다 적으면(미달이지만 0은 아니면) 최저 청약가가 공모가가 되고
청약분만큼만 발행됩니다.

## 8. 그 외 정확히 파악하신 것들 — 그대로 유효합니다

- 시작 자산 현금 100만원, **주식 0주**. 청약 안 하면 끝까지 0주 ✓
- 무상증자는 **보유자에게만** 비례 배정, 주식 없으면 0주 ✓
  — "보유 자체가 보상받는 구조"라고 쓰신 게 정확합니다. 실측으로도 그렇고,
  그래서 증자 상한을 5%로 낮춰 그 보상을 억눌렀습니다(높이면 '그냥 들고 있기'가 최적 전략이 됩니다)
- 수익률은 `nav / invested - 1`, `invested` 에 월급이 누적된다 ✓
- 무행동자 수익률이 **정확히 0%** ✓
- `NO_COUNTERPARTY` 는 예외가 아니라 정상 상황 ✓ (매도 호가는 전체 시간의 약 19% 동안 빕니다)
- `depth` 는 값이 있는 호가만 오므로 사다리에 구멍이 생긴다 ✓
- 호가 단위 5/10/25원, 최소 거래 10주, 수수료 편도 0.15% ✓
- 봇 30명 기본, 시상 제외 ✓
- 종목 색이 다크 배경에서 안 보인다 ✓ — 서버 값은 실제 교색이라 그대로는 못 씁니다

## 10. 그 뒤에 추가된 운영 기능 (커밋 04656de 이후)

화면에 직접 영향을 주는 것만 추립니다. 전체는 `docs/API.md` 를 보세요.

### 반드시 반영해야 하는 것: `join` 에 `deviceId`

```jsonc
POST /api/rooms/{code}/join
{ "name": "앨리스", "deviceId": "localStorage 에 보관한 임의 문자열" }
```

**이걸 안 보내면 새로고침한 참가자가 게임에서 영구히 튕겨 나갑니다.**
50명이 모이면 새로고침하거나 통신이 끊기는 사람이 반드시 나옵니다.
`deviceId` 가 있으면 같은 기기로 다시 들어올 때 원래 참가자로 복귀하고
`playerToken` 도 그대로 돌아옵니다(`resumed: true`). 게임이 시작된 뒤에도 복귀는 됩니다.

`crypto.randomUUID()` 를 `localStorage` 에 한 번 저장해 두고 계속 쓰면 됩니다.
화면을 열 때는 `POST /resume` 로 보관한 토큰이 아직 유효한지 먼저 확인하세요.

### 이름 표시는 반드시 서버 응답의 `name` 을 쓰세요

제어문자·줄바꿈이 제거되고 연속 공백이 줄고 12자로 잘립니다.
**같은 이름이 이미 있으면 뒤에 번호가 붙습니다**(`김철수` → `김철수2`).
입력값을 그대로 그리면 서버가 보관한 이름과 달라집니다.

### 새 화면 요소 세 가지

| 필드 | 화면 |
|---|---|
| `snapshot.paused` | 일시정지 오버레이. 방장이 멈추면 게임 시간도 멈춥니다 |
| `snapshot.connections` | 대기실·방장 화면의 "접속 중 47명" |
| `GET /result.csv` | 결과 화면의 내려받기 버튼. `<a href download>` 로 바로 연결 |

### 방장 화면에 넣을 만한 것

- `POST /pause` · `/resume-game` — 일시정지·재개
- `POST /kick` `{playerId}` — 참가자 내보내기
- `POST /config` — 시작 전 봇 수·진행 시간 변경 (2번 대기실)

### 429 를 만날 수 있습니다

주문은 참가자당 초당 12건(버스트 25)으로 제한됩니다. 화면에서 연타를 막고 있다면
사실상 만날 일이 없지만, 재시도 로직이 있다면 `RATE_LIMITED` 와 `Retry-After` 헤더를 처리하세요.
